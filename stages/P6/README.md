# P6｜让系统出错时可控制

这一阶段不再增加主要产品功能。选择 P3 或 P5 的项目，用真实失败数据把它改造成可评测、可观测、可恢复、成本受控的系统。

## 先冻结基线

记录当前版本在固定样本上的质量、延迟、Token、费用和常见故障。没有基线，就无法判断后面的“优化”是否有效。

随后让每次请求可以被追踪：结构化日志、链路标识、模型和 Prompt 版本、耗时与费用。针对真实故障加入超时、重试、回退、缓存或预算限制，并通过故障注入验证。

安全检查至少覆盖提示注入、敏感数据、越权工具调用和审计记录。有副作用的工具使用最小权限、参数校验和人工确认。

## 完成信号

- 有固定评测和人工检查，能比较两个版本。
- 一次请求的关键步骤、耗时和费用可以追踪。
- 超时、依赖故障或费用异常有明确回退。
- 提示注入、隐私和工具权限经过测试。
- 完成一次供应商或关键依赖变化演练。
- 外部评审者提出问题后，完成修改和再验证。
