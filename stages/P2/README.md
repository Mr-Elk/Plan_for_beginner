# P2｜把工具做成后端服务

这一阶段要理解一次请求怎样经过接口、业务逻辑和数据库。售后工具会变成一个可部署的 API，客服账号只能访问被允许的数据。

## 先打通一条请求

选择“创建并查看工单”作为第一条主线：定义请求和响应，设计工单与用户表，用 FastAPI 接收请求，用 PostgreSQL 保存，再写集成测试。

主线跑通后加入登录、权限、输入校验、迁移和日志。然后把 P1 的结构化 AI 功能放到独立服务边界中，记录固定样本、失败、延迟和费用。

最后在 Linux 服务器部署一个完整切片。网页可以暂时很薄，不能用界面掩盖 HTTP、SQL 或权限问题。

## 需要真正理解的内容

- HTTP 方法、状态码和 JSON 契约；
- 表关系、SQL、索引和事务；
- 路由、业务逻辑与持久化的分层；
- 认证、授权、配置、日志和集成测试；
- 常见接口和数据库故障怎样定位。

## 完成信号

- 能从用户流程写出接口、数据模型和验收场景。
- API 有数据库、认证、权限、测试和迁移。
- 一个纵向切片能在 Linux 上重复部署。
- 能解释请求经过哪些层，并独立排查一个故障。
- 完成一次 Issue/PR 评审—修改闭环和陌生后端变式。
