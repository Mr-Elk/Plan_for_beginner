# P3｜让客服真正用上

这一阶段把 API 变成别人能使用的产品。一个不了解代码的客服，应能登录、提交售后记录、查看 AI 整理结果，并再次找到历史工单。

## 只做一条完整用户流程

先用 React 完成表单、请求、加载、结果和错误提示。界面只服务核心流程，不同时学习多套前端框架，也不先做复杂页面。

随后处理真实使用会遇到的问题：文件上传、搜索或分页，网络和模型失败，用户越权，配置错误。前端隐藏按钮不是权限控制，后端必须再次检查。

用 Docker 在 Linux 上部署，自动运行测试，并加入足够定位问题的日志。重试、缓存、限流和后台任务只在真实失败需要时加入。

找一个没参与开发的人，只给他访问方式和 README。观察他是否能完成任务，把最重要的卡点修掉。

## 完成信号

- 目标用户、核心流程和非目标写清楚。
- 用户能通过网页完成登录、提交和查询。
- 权限、主要错误、测试、日志和部署存在。
- 干净环境可以重新运行系统。
- 学习者能现场完成一次前后端修改并解释数据流。
- 有一份可复查的外部使用反馈和对应修订。
