# 阶段任务目录

本目录把[48周路线图](../docs/01-roadmap.md)拆成P0–P7八个阶段任务清单。阶段任务回答“这一阶段需要完成哪些能力增量”，周任务回答“本周承诺完成哪一小段”，两者不能互相替代。

## 1. 目录层级

```text
stages/
  P0/
    stage-tasks.md        # 全年基线中的阶段任务清单
    stage-contract.md     # 仅在P0成为当前阶段时创建并批准
    weeks/                # 批准合同后按周创建任务
    course-packs/         # 每两周一个执行合同
    reviews/              # 周复盘和阶段验收
  P1/ ... P7/             # 使用相同层级，按进入顺序逐步实例化
```

Git不保存空目录，因此`weeks/`、`course-packs/`和`reviews/`在对应产物首次出现时创建。

## 2. 三层任务边界

| 层级 | 时间范围 | 作用 | 允许的细度 |
|---|---|---|---|
| 阶段任务清单 | P0–P7全年可见 | 冻结阶段范围、依赖、产物和能力门映射 | 任务组，不分配到具体日期 |
| 阶段合同 | 仅当前阶段 | 根据真实入口批准主项目、切片、课程包和验收 | 只详细到两周课程包结果 |
| 周任务 | 当前课程包 | 冻结本周可执行承诺和验收 | 可直接执行的学习块与项目增量 |

阶段任务清单不是已批准合同，也不证明任务已经完成。未来阶段只保持规划积压状态；学习者进入该阶段前，必须根据最新证据筛选任务并创建阶段合同。

## 3. 追溯规则

- 阶段任务使用稳定ID：`ST-P0-01`至`ST-P7-xx`。
- 依赖必须写完整ID；连续范围写成`ST-Px-01–ST-Px-05`，不得省略第二个ID前缀。
- 阶段合同必须引用纳入本期的阶段任务ID，并说明删除、合并或降级的任务。
- 周任务必须引用所属课程包、阶段任务ID和能力门条款。
- 一个周任务可以服务多个阶段任务，但同一时间仍只有一个主交付功能。
- 阶段任务完成状态只能由真实产物和证据更新，不能按计划日期自动完成。

## 5. 当前推进顺序

1. 审阅八个阶段的范围和依赖，不填写虚假完成状态。
2. 只为当前P0创建并批准`stage-contract.md`。
3. 从P0合同拆出课程包，再拆当前周任务。
4. P0结束后依据证据修订P1任务选择，不机械照抄全年积压。
