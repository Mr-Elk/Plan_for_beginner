# 从这里开始学习

这套路线不是让你先读完一堆规划文件。每次只打开当前阶段，先知道要做出什么，再从项目遇到的问题里学习Python、后端、数据和AI。

默认项目主线是一套逐步成长的“个人资料与知识助手”：先做命令行工具，再变成API和Web产品，之后加入数据判断、检索、评测和生产质量。项目题材可以换，但同一时间只做一个主项目。

## 八个阶段会把项目带到哪里

1. [P0｜先把编程跑起来](P0/README.md)：跑通环境，做两个小工具，找到真实起点。
2. [P1｜做出第一个有用的Python工具](P1/README.md)：能够保存数据、处理错误、写测试，并独立完成变式。
3. [P2｜把工具变成可以调用的服务](P2/README.md)：加入API、数据库、用户和权限，部署到Linux。
4. [P3｜让别人真的用上产品](P3/README.md)：补上网页、完整用户流程和外部使用反馈。
5. [P4｜判断什么时候该用模型](P4/README.md)：从数据和简单基线出发，完成一个机器学习闭环。
6. [P5｜让AI查资料或安全做事](P5/README.md)：选择RAG或工具工作流，亲手实现并检查失败。
7. [P6｜让AI系统出问题也能管](P6/README.md)：加入评测、观测、恢复、安全和成本控制。
8. [P7｜把能力变成工作机会](P7/README.md)：收敛旗舰项目，接受外部评审并进入真实投递。

不用现在读完P1–P7。它们只告诉你大方向，不是已经排好的作业。当前还没有正式开训，应先阅读[P0阶段指南](P0/README.md)。

## 阶段指南怎样使用

- 先读“这一阶段要做成什么”，不要先背知识目录。
- 和负责人一起选定一个主项目或当前增量。
- 进入阶段后再把指南拆成两周课程包和本周任务。
- 项目暴露哪个主要缺口，就补哪部分知识；不要因为一个Bug回炉整门课。
- 是否进入下一阶段看独立完成和真实产物，不看视频进度。

## 给负责人和课程AI

每个阶段有两种视图：

```text
Px/
  README.md             # 学习者入口：目标、项目成长顺序和完成信号
  stage-control.md      # 管理视图：任务ID、依赖、门条款和证据要求
  stage-contract.md     # 只在成为当前阶段后创建和批准
  course-packs/         # 当前阶段滚动生成的两周课程包
  weeks/                # 从课程包拆出的当周任务
  reviews/              # 周复盘和阶段验收
```

Git不保存空目录，因此后四类执行产物在首次使用时再创建。未来阶段的指南和控制表是规划参考，不代表合同获批、任务完成或能力通过。
