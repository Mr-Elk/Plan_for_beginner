# 阶段学习地图

不用先读完整规划。每次只看当前阶段：先做出一个真实结果，再从项目里的问题学习编程、后端、数据和 AI。

默认项目是一套“小型电商售后与知识助手”。它会持续成长，不是八个互不相关的 Demo：

1. [P0｜把程序跑起来](P0/README.md)：完成两个 CLI，确认真实起点。
2. [P1｜独立做一个 Python 工具](P1/README.md)：保存、查询和测试售后工单。
3. [P2｜把工具做成后端服务](P2/README.md)：加入 API、数据库、用户和权限。
4. [P3｜让客服真正用上](P3/README.md)：补网页、部署和外部反馈。
5. [P4｜判断是否需要机器学习](P4/README.md)：建立工单分类基线和错误分析。
6. [P5｜让 AI 查资料或调用工具](P5/README.md)：完成 RAG 或受控工作流。
7. [P6｜让系统出错时可控制](P6/README.md)：加入评测、观测、恢复、安全和成本。
8. [P7｜把项目变成求职证据](P7/README.md)：收敛旗舰项目并进入真实投递。

阶段不是按日期自动结束。完成信号必须有代码、测试、独立任务和解释支持。当前尚未开训，只需阅读 [P0](P0/README.md)。

每个阶段目录还有一份 `stage-control.md`，供负责人管理任务编号和能力门；学习者不需要先读。阶段合同、课程包和周任务只在该阶段开始时创建。
