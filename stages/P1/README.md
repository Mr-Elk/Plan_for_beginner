# P1｜做出第一个真正有用的Python工具

这一阶段的核心不是“看完Python语法”，而是独立做出一个自己或身边人愿意使用的小工具。Python知识会在项目需要时进入，用过、改过、解释过，才算真正学会。

默认可以做一个“学习资料整理器”：保存资料、添加标签、搜索内容，再用AI完成一个受控的小功能。也可以换成待办管理、记账、文本处理等题目，但只选一个项目。

## 项目会这样长出来

### 先说清楚它解决什么

找一个小而具体的问题，写出三组真实例子：用户输入什么，希望得到什么，哪些情况应该报错。暂时不要从框架或界面开始。

### 写出最小可用版本

先用函数、列表和字典完成核心流程。代码开始变长时，再拆成模块；错误真实出现时，再学习异常处理。目标是让代码结构跟着问题成长，而不是先套一层看不懂的“标准架构”。

### 让数据下次还能找到

先把数据保存为JSON文件，理解读写和数据格式；功能稳定后再迁移到SQLite，加入新增、查询、修改和删除。迁移前后都要能运行，不要直接复制数据库模板。

### 加入一个克制的AI功能

例如自动生成标签、整理摘要或判断文本类别。输入和输出格式要固定，模型返回错误内容时程序不能直接崩溃。AI功能只是工具的一部分，不是整个项目。

### 把“能跑”变成“放心改”

给核心逻辑补测试，保留至少一个真实Bug和回归测试；补齐安装、运行和示例说明。请一个不了解代码的人照着README运行一次，看看他会卡在哪里。

### 最后证明不是照着答案做出来的

关掉AI和完整示例，在限定时间内做一个陌生小程序；再给主项目增加一个没有提前练过的需求。你需要自己澄清需求、修改代码、补测试并解释取舍。

## 项目之外保留两条轻量训练

- 每周做少量算法与数据结构练习，重点讲清楚为什么用列表、字典、栈、队列或树，而不是追求题量。
- 持续阅读与当前问题相关的英文报错和官方文档，允许翻译，但结论必须靠代码验证。

这两条训练为项目服务，不另开两门主课。

## 离开这一阶段前，问自己

- 我能把一个小需求拆成输入、输出、规则和边界吗？
- 我能把程序拆成几个职责清楚的函数和模块吗？
- 我能处理文件、数据保存、异常和测试吗？
- 没有AI提供完整答案时，我还能从空文件开始吗？
- 换一个相似需求，我知道哪些代码应该保留、哪些应该重写吗？

如果答案大体为“能”，而且代码、测试和现场修改能够证明，就可以准备进入后端阶段。
