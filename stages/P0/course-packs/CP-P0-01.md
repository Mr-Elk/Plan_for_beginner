# CP-P0-01 第 1–2 周开训诊断课程包

两周只推进一个项目：先把虚构售后文本整理成文件，再用一次受控模型调用生成结构化处理草稿。项目、练习和验收共用这条数据流。

## 1. 基本信息

- 对应任务：`ST-P0-02` 至 `ST-P0-09`
- 对应门：G0-01 至 G0-05
- 当前能力入口：缺失，教学前 A0 基线完成后更新
- 阶段合同：[P0 开训诊断阶段合同](../stage-contract.md)
- 状态：草案，待负责人和学习者批准；批准后进入 S0 检查
- 计划投入：两周各 40 个有效小时；时间用于校准负荷，不证明能力
- 最高 AI 等级：练习通常 A0–A2；基线与 G0 验收 A0

只有 [S0](../../../docs/14-program-control.md#3-s0-正式开训门) 通过后才能开包。模型供应商、官方 Python 快速入门、预算和密钥位置尚未确认，因此第 2 周真实调用当前仍是阻塞项。

## 2. 两周唯一主结果

| 周 | 唯一主结果 | 结束证据 |
|---|---|---|
| 第 1 周 | 普通 CLI 可以读取、整理、统计和保存虚构售后文本 | A0 基线、代码、失败测试、Git、T1 变式和周复盘 |
| 第 2 周 | 模型 CLI 可以安全调用一次模型并保存结构化草稿 | 延迟重建、假响应测试、受控调用、README、A0 变式和 G0 审查 |

执行槽位固定为一条主交付流、一条必要基础流和一条轻量复习流。普通 CLI 未达到第 1 周退出条件时，不开启模型功能。

## 4. 项目公开规格

```text
虚构售后文本
→ 普通 CLI 清理、统计并保存
→ 模型 CLI 读取整理结果
→ 验证并保存摘要、类别和优先级
```

### 普通 CLI

- 输入：一个 UTF-8 虚构售后文本文件。
- 输出：清理后的文本、至少两项简单统计和结果文件位置。
- 失败：文件不存在、空文本或无法读取时明确失败，不生成伪成功结果。
- 结构：文本处理逻辑与终端输入输出分开；正常和失败路径都能单独测试。

### 模型 CLI

- 输入：普通 CLI 的整理结果；供应商和模型由 S0 唯一确定。
- 配置：密钥只从环境变量读取，仓库只保留 `.env.example`。
- 输出：可保存的结构化草稿，至少包含摘要、类别和优先级。
- 失败：配置缺失、请求失败、超时、非法响应或字段缺失时明确停止。
- 测试：自动测试使用固定假响应；至少覆盖正常响应、缺字段、非法响应和配置缺失。
- 真实调用：只使用虚构数据做一次预算内冒烟验证，不把密钥写入代码、日志、提示或 Git。

明确不做：数据库、Web、前端、RAG、Agent、多供应商比较、复杂类设计和模型效果优化。

## 5. 学习安排与资料

| 内容 | 进入方式 | 唯一主资料 | 项目使用点 |
|---|---|---|---|
| 终端、Python 运行和报错 | 若诊断为 L0，先看最小例子并立即修改 | [P0 最小知识地图](../materials/p0-minimal-guide.md) | 建项目、运行、制造和修复错误 |
| 字符串、条件、循环、函数和容器 | 先预测或补全，再关闭示例重建 | [P0 最小知识地图](../materials/p0-minimal-guide.md)及 [Python 教程](https://docs.python.org/3/tutorial/)当前小节 | 文本清理、统计和结构化数据 |
| 文件、异常和测试 | 从项目失败路径进入 | [P0 最小知识地图](../materials/p0-minimal-guide.md)与本包规格 | 读写、空输入、文件错误和回归测试 |
| Git | 跟做一次后独立说明 | 本地 `git help` | 状态、提交、日志和忽略文件 |
| 项目环境 | 从空目录重复创建 | [uv 项目初始化](https://docs.astral.sh/uv/concepts/projects/init/) | 初始化、运行和依赖记录 |
| 模型 API | 先画数据流和解析假响应 | 待 S0 选定供应商；若使用 OpenAI，查[官方 API 快速入门](https://developers.openai.com/api/docs/quickstart) | 一次调用、结构验证和错误处理 |

公开输入和假响应见[练习样例](../materials/public-samples.md)。资料缺失标记为缺失，不能让 AI 猜测版本敏感命令或接口。每次学习按[高效学习步骤](../../../docs/13-efficient-learning-process.md)完成首试、精准输入、重建和变式。

## 6. 练习与支架撤除

| 练习 | AI 边界 | 撤除方式 | 通过信号 |
|---|---|---|---|
| 修改最小 Python 输出并解释变化 | A0–A1 | 换输入和条件后从空白写 | 运行结果与解释一致 |
| 把文本处理拆成函数 | A0–A2 | 关闭示例重写核心函数 | 函数可以单独测试 |
| 处理普通 CLI 的错误输入 | A0–A2 | 更换文件内容或路径 | 错误明确且有回归测试 |
| 解析模型假响应 | A0–A2 | 改成缺字段或非法响应 | 程序拒绝伪完整结果 |
| 陌生文本规则修改 | A0–A1 | 未污染 T1 题面 | 代码、测试和解释一致 |

A3 只允许用于非核心 SDK 阻塞。使用后必须标记债务，增加一个 AI 未提供的失败测试，并在 24–72 小时内用更低辅助重写。

## 7. 独立检查

- 教学前基线：A0；由验收者冻结时间和允许资料，只保存原始代码、用时、卡点和错误类型。
- 第 1 周检查：改变输入格式或失败条件，完成普通 CLI 的 T1 变式。
- 第 2 周检查：重建普通 CLI 核心流程，完成未见过完整答案的小程序或现有 CLI 陌生修改。
- 综合说明：现场运行、定位一个错误、说明 Git 改动、解释模型数据流和密钥边界。
- 私有边界：题面、答案、隐藏测试和评分锚点不进入仓库或辅导 AI。

G0-01 至 G0-05 的权威检查和证据要求见[阶段合同](../stage-contract.md#5-g0-验收)。同一原始产物可以支持多个门条款，但不要重复登记为多个事实。
