# P0 最小知识地图

这不是一门压缩版 Python 课。学习者先做首试，只在卡住时打开对应小节，解决后立即回到项目。

## 1. 先看懂程序现场

一次命令至少要知道四件事：当前位于哪个目录、运行了什么、产生了什么输出、退出时是否成功。先会使用 `pwd`、`ls`、`cd` 和 `mkdir` 观察目录，再运行 Python 文件。

报错时先读最后一个具体错误和对应文件行号。不要先复制整段报错问 AI；先写出预期、实际和最小复现。

完成检查：能从空目录建立项目，运行一个 Python 文件，故意制造错误并恢复。

## 2. 把 Python 看成数据流

```text
输入文本
→ 保存到变量
→ 条件和循环决定怎样处理
→ 函数完成一个明确步骤
→ 列表或字典保存多个值
→ 输出到终端或文件
```

| 概念 | 当前只需要理解 | 项目中的位置 |
|---|---|---|
| 字符串 | 文本可以切分、去空白和组合 | 清理售后文本 |
| 条件 | 根据真假选择行为 | 空文本时停止 |
| 循环 | 对多行或多个值重复处理 | 统计非空行 |
| 函数 | 一组输入产生一个结果 | 分开读取、清理和统计 |
| 列表 | 按顺序保存多个元素 | 保存有效文本行 |
| 字典 | 用字段名保存结构化值 | 保存摘要、类别、优先级 |

完成检查：能不用术语，沿着实际输入解释数据怎样变成输出。

## 3. 文件、错误和测试

文件路径只是位置，不等于文件一定存在。读取前要考虑不存在、没有权限、编码不符合预期和内容为空。

异常处理的目标是把“哪里失败、为什么、用户下一步做什么”说明白，不是用一个大 `try/except` 隐藏所有错误。

最小测试至少回答：给定正常输入是否得到预期结果；给定一个失败输入是否明确失败。修复 Bug 后保留能复现原问题的测试。

完成检查：核心文本处理可以脱离终端单独调用，正常和失败路径都能重复验证。

## 4. Git 只保存有意义的变化

```text
工作区修改
→ 查看状态和差异
→ 暂存本次相关文件
→ 提交并说明“改了什么、为什么”
```

不要按时间机械提交，也不要把所有改动堆到最后。真实密钥、`.env`、缓存和临时输出不进入仓库；仓库只保留 `.env.example` 说明需要哪些变量。

完成检查：能查看历史，并用自己的话说明两个关键提交之间发生了什么。

## 5. 模型 API 是一次外部请求

```text
程序读取环境变量
→ 构造请求
→ 模型服务返回响应
→ 程序验证结构
→ 合法才保存，失败则明确停止
```

先用固定假响应完成解析和失败测试，再按批准的官方资料做一次真实调用。网络成功不代表业务成功；缺字段或格式错误仍然必须拒绝。

如果使用 OpenAI API，按[官方 API 快速入门](https://developers.openai.com/api/docs/quickstart)单独创建 API Key、设置环境变量并验证可用额度。不要把 ChatGPT 登录状态或订阅当作程序已经能调用 API。

完成检查：能画出请求和响应的数据流，解释密钥为什么不能写进代码，并让假响应测试不产生费用。
