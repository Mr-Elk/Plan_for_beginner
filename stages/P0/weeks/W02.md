# P0 第 2 周：模型 CLI、延迟重建与 G0 验收

本周继续同一个“售后文本整理器”项目：先确认普通 CLI 可以脱离答案重建，再增加模型 CLI，最后完成 G0 独立检查。完整模型输入输出与测试要求见[课程包项目规格](../course-packs/CP-P0-01.md#模型-cli)。

## 1. 三个结果

### 结果一：重建普通 CLI（7 小时起始预算）

- 关闭同题完整答案，从空白重建核心文本处理流程；更换输入或规则完成 T1 近迁移，并记录辅助差距（WT-P0-W02-01；ST-P0-04、ST-P0-07）。

完成信号：核心流程可以从空白开始；新条件下测试仍能通过；卡点和 AI 等级有原始记录。

### 结果二：完成模型 CLI（28 小时起始预算）

- 确认唯一供应商的官方资料、预算、环境变量和虚构数据边界（WT-P0-W02-02；ST-P0-05）。
- 画出数据流，先用假响应解析，再进行一次预算内真实调用并保存验证后的字段（WT-P0-W02-03；ST-P0-05）。
- 测试正常响应、缺字段、非法响应和配置缺失，不在自动测试中产生真实费用（WT-P0-W02-04；ST-P0-05、ST-P0-07）。
- 更新 README、.env.example 和 Git 历史，让负责人可在干净终端复现（WT-P0-W02-05；ST-P0-06）。

完成信号：课程包公开规格全部可演示；真实密钥未进入代码、日志、提示或 Git；失败不会被保存成伪成功结果。

### 结果三：完成 G0 检查与阶段决定（5 小时起始预算）

- 在 A0 下完成未污染的小程序或陌生修改，现场运行、定位错误并说明 Git 和模型数据流（WT-P0-W02-06；ST-P0-09）。
- 汇总两周真实时间、AI、债务、精力和注意力，由负责人和验收者审查 [G0-01 至 G0-05](../stage-contract.md#5-g0-验收)（WT-P0-W02-07；ST-P0-08、ST-P0-09）。

完成信号：每项结论都指向原始证据；缺失仍标缺失；没有提前宣称晋级。

## 2. 推荐顺序

1. 先完成普通 CLI 延迟重建，确认第 1 周缺口。
2. 使用[公开假响应](../materials/public-samples.md)打通结构解析和失败测试。
3. 查已经批准的官方资料，完成一次受控真实调用；若使用 OpenAI，API Key 与可用额度必须按[官方 API 快速入门](https://developers.openai.com/api/docs/quickstart)单独验证。
4. 集成 README、配置示例和 Git 历史，做干净运行检查。
5. 关闭辅导上下文，完成 G0 变式、讲解和阶段复盘。

如果 A3 帮助解决了非核心 SDK 阻塞，必须增加一个 AI 未提供的失败测试，并在 24–72 小时内用更低辅助重写。供应商、预算或密钥未确认时，停止真实调用；假响应练习不能冒充 ST-P0-05 通过。

## 3. 项目讲解

学习者依据自己的项目说明四件事，不背标准答案：

1. 两个 CLI 分别解决什么问题，为什么按这个顺序完成？
2. 文本怎样经过函数、请求、响应验证变成保存结果？
3. 展示一个失败案例和修复过程，说明怎样防止复发。
4. 哪部分得到过最高 AI 帮助，撤除后怎样验证？

## 4. 阶段结束记录

执行后只记录事实：

- 项目仓库、提交、测试、演示和 A0 变式证据。
- 最高 AI 等级、未清债务、有效时间和可持续性。
- G0-01 至 G0-05 的证据 ID 和验收者结论。
- P0 结论：晋级、条件晋级或返回补修。
