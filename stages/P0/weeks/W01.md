# P0 第 1 周：环境、基线与普通 CLI

本周只做成一件主事：让“售后文本整理器”的普通 CLI 可以运行、测试和说明。完整输入输出与失败要求见[课程包项目规格](../course-packs/CP-P0-01.md#4-项目公开规格)。

开始前必须通过 S0。环境修复、角色确认和私有材料隔离属于开训准备，不计入本周 40 个有效小时。

## 1. 三个结果

### 结果一：留下真实起点并建立可重复环境（11 小时起始预算）

- 只复核 S0 的环境冒烟结果，不讲 Python 语法，也不分析诊断题（WT-P0-W01-01；ST-P0-02）。
- 在任何 Python 教学前完成私有 A0 基线，保留原始代码、用时、卡点和错误（WT-P0-W01-02；ST-P0-03）。
- 基线封存后，从空目录建立并运行学习项目；初始化 Git 和 .gitignore，至少完成两个有明确目的的增量提交（WT-P0-W01-03；ST-P0-02、ST-P0-06）。

完成信号：命令可以重复；学习者能说明当前目录、错误位置和关键提交；基线没有被事后美化。

### 结果二：完成普通 CLI（23 小时起始预算）

- 读取虚构文本，清理多余空白，计算至少两项简单统计并保存结果；把核心处理与终端输入输出分开（WT-P0-W01-04；ST-P0-04）。
- 处理文件不存在、空文本和至少一个输入格式问题，为正常与主要失败路径补最小测试（WT-P0-W01-05；ST-P0-04、ST-P0-07）。

完成信号：公开规格全部可演示；至少一个 Bug 有复现、原因、修复和回归测试。

### 结果三：独立检查并决定第 2 周入口（6 小时起始预算）

- 阅读一小段当前所需官方资料，用中文复述并现场验证（WT-P0-W01-06；ST-P0-07）。
- 在 A0–A1 下完成 T1 变式，演示 CLI，并记录 AI、时间、精力、注意力和卡点（WT-P0-W01-07；ST-P0-07、ST-P0-08）。

完成信号：原始证据可定位；负责人能够区分能力缺口、环境问题和负荷问题。

## 2. 推荐顺序

1. 只复核环境能运行；在接触任何 Python 教学前完成 A0 基线。
2. 让最小项目从空目录运行起来，同时建立 Git。
3. 先打通“读取—处理—输出”，再增加保存和统计。
4. 主动制造错误，补失败行为和测试。
5. 关闭完整答案完成变式，最后演示和复盘。

每个任务使用[高效学习步骤](../../../docs/13-efficient-learning-process.md)：先定义结果和首试，再只补当前缺口，随后关闭示例重建、变式、测试和提交。每天按 [P0 辅导会话](../tutor-guide.md)启动，卡住时从 [A1 提示](../../../docs/04-ai-use-policy.md)开始升级。

## 3. 第 2 周进入条件

只有以下条件同时满足，才开始模型 CLI：

- 普通 CLI 的正常路径可以重复运行，至少一个失败路径已有测试。
- 学习者能说明输入、核心函数、输出和一次错误修复。
- Git 历史和 README 可检查，没有未清偿的 A3/A4 核心代码。
- 模型供应商、官方资料、预算和密钥位置已经通过 S0 检查。

前三项未满足时，第 2 周先补普通 CLI；不能为了赶进度开启第二个主功能。

3. AI 撤除后能否继续，是否留下学习债务？
4. 40 小时安排应保持、降载还是进入恢复？
