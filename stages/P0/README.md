# P0｜先把编程跑起来

这是正式训练前的起跑阶段。目标不是两周学完Python，而是确认你能在自己的电脑上写、运行、修改程序，并找到适合自己的学习起点。

阶段结束时，你手里应该有两个很小但真实可运行的程序：一个普通命令行工具，一个会调用大模型的命令行工具。它们不需要漂亮，代码也不需要高级，但每一段关键代码你都要能说清楚。

## 从这五件事开始

### 1. 让电脑跑起第一段代码

在WSL里创建项目，运行一个Python文件，故意制造一次报错，再把它修好。顺手完成第一次Git提交。

这里需要学的只有当前操作会用到的内容：终端怎样进入目录、Python文件怎样运行、项目依赖放在哪里、报错从哪一行开始看。

### 2. 做一次不求高分的起点测试

在没有AI代写的情况下，尝试完成一个很小的编程题。不会也没关系，保留写到一半的代码、报错和思路。

这不是淘汰考试。它只帮助我们判断：应该从变量和循环开始，还是可以直接进入函数、文件和小项目。

### 3. 做出第一个普通工具

从一个能在当天用上的小功能开始，例如：

- 统计一段文字的字数和高频词；
- 批量整理某个测试目录里的文件名；
- 记录待办并按状态查询；
- 读取一份文本并生成简单摘要报告。

先让正常输入跑通，再处理空输入、文件不存在和格式错误。不要一次加入很多功能。

### 4. 给工具接上一次模型调用

让程序接收一段文字，调用模型完成一种明确任务，例如提取关键词、改写标题或生成结构化摘要。

这一小步重点不是提示词技巧，而是看懂数据怎样从程序发出去、结果怎样回来，以及密钥为什么不能写进代码和Git。

### 5. 关掉答案，再做一个相似版本

换一组输入或换一个小需求，自己重新写主要流程。完成后讲清楚：程序从哪里开始、数据经过了哪些步骤、哪里最容易出错、你向AI求助了什么。

## 贯穿进行的小习惯

- 每次完成一个有意义的改动就提交Git，并用一句人话说明改了什么。
- 遇到报错先读最后几行，写下自己的判断，再决定是否求助。
- 用翻译工具读一小段官方文档，然后通过实际运行验证理解。
- 如实记录一周真正投入在代码、测试、解释和复盘上的时间，不追求把数字写满40小时。

## 什么时候算完成

- [ ] 两个工具都能在新的终端会话中重新运行。
- [ ] 密钥没有进入代码或Git历史。
- [ ] 能独立修改一个小需求，而不是只能重复原示例。
- [ ] 能说明一次报错的原因和修复过程。
- [ ] 有第一份真实学习时间和疲劳记录，可以决定下一阶段从哪里开始。

如果这些事情还做不到，只补对应缺口，不需要重学整个阶段。
