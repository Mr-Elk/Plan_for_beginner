# P0｜把程序跑起来

这一阶段不要求学完 Python。目标是确认你能在自己的电脑上创建项目、运行代码、修一次错误，并留下真实的起点数据。

## 开始入口

1. 先读两份周任务，确认每一步知道要做什么。
2. 和负责人完成[P0 开训检查](start-checklist.md)；只有 S0 判定为“通过”才开始计时。
3. 开训后从[第 1 周](weeks/W01.md)开始，每天按[AI 辅导入口](tutor-guide.md)发起学习会话。

私有诊断题、答案和评分表不会出现在本仓库。还没有通过 S0 时，不提前学习诊断题涉及的 Python 内容。

## 要做的两个程序

第一个是普通 CLI。可以读取一份售后聊天文本，统计字数、提取订单号，或按简单规则生成摘要。

第二个在前一个程序上加入一次模型调用，让模型把文本整理成固定字段，例如：订单号、问题类型、用户诉求和紧急程度。密钥必须放在环境变量中，不能写进代码和 Git。

## 建议顺序

1. 只做环境冒烟确认，不接受 Python 讲解。
2. 在无 AI 条件下做一次短诊断；不会的部分保留原样。
3. 在 WSL 中创建学习项目，运行第一个 Python 文件并提交 Git。
4. 完成普通 CLI，处理空文本和文件不存在。
5. 接入模型，处理超时、错误响应和格式不正确。
6. 关闭答案，换一份输入或一个小需求重新写主要流程。
7. 记录真实投入、精力和最常见卡点。

遇到报错时先读错误位置，写下预期、实际和自己的判断，再求助。这里重点是学会运行、修改和验证，不是追求漂亮架构。

## 完成信号

- 两个 CLI 都能在新的终端中重新运行。
- 能独立修改一个小需求并解释程序怎样处理数据。
- 至少处理一个错误输入，并为核心逻辑写最小测试。
- Git 历史能说明几次关键改动，仓库里没有密钥。
- 有一次无 AI 诊断和一周真实负荷记录。
