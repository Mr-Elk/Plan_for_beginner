# P5｜让 AI 查资料或调用工具

这一阶段只选一个主形态：让 AI 从售后规则中检索并引用依据，或者在人工确认后调用退款、改地址等受控工具。另一个形态最多做小型练习。

## 先不用复杂框架

先固定输入输出契约，亲手连起模型、检索或工具调用。这样才能看见每一步的参数、状态和失败。底层原型稳定后，再判断框架是否真的减少复杂度。

做知识检索时，要检查文档处理、切分、召回、重排、引用和最终回答；不能只看答案顺不顺。做工具工作流时，要校验参数、限制权限、记录状态，并在有副作用的操作前要求确认。

建立一组固定样本，记录正确性、引用或工具结果、延迟和费用。每次修改前后都用同一批样本比较。

## 完成信号

- 能说明为什么选择规则、检索、ML 或 LLM。
- 不依赖复杂框架也能解释完整调用链。
- RAG 有可检查的来源引用，或工具调用有参数和权限边界。
- 有固定评测、失败分类和一次前后对比。
- 能诊断一次召回、生成或工具执行失败。
- 换一批资料或一个工具后，仍能独立完成变式。
