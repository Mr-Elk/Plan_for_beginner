# P5｜让AI查得到资料，也能安全地做事

这一阶段深入两类常见AI应用：根据资料回答问题，或者调用真实工具完成操作。你只选其中一种作为主项目，另一种最多做一个小练习。

如果延续“学习资料整理器”，比较自然的主线是把它升级成一个带引用的知识助手：回答问题时能够指出依据来自哪份资料，而不是只生成一段看起来合理的话。

## 第一步不是选框架

先写下真实用户动作、输入、期待输出和不能接受的失败。比较简单规则、关键词搜索、传统检索和大模型，确认复杂AI方案确实带来价值。

把输出格式固定下来，准备几条正常、边界和错误样本。之后每次改动都用同一批代表性问题检查，避免只凭感觉评价结果。

## 亲手连起最小链路

如果选择知识助手，就先完成：读取文档、切分内容、建立表示、召回片段、生成答案、附上引用。

如果选择工具助手，就先完成：定义工具参数、校验输入、调用工具、保存状态、展示结果，并在真正执行前要求用户确认。

先用清楚的Python代码看见每一步，再决定是否需要一个高层框架。框架只能减少已经理解的重复劳动，不能藏住尚未理解的过程。

## 专门研究它会怎样失败

准备一些会找不到资料、找到错误资料、问题含糊、输出格式错误或工具执行失败的案例。逐个判断问题发生在输入、检索、生成、参数还是外部服务。

修改后重新跑固定样本，同时记录响应时间和费用。优化必须说明改善了什么，又牺牲了什么。

## 让别人试用并追问你的设计

请外部使用者完成一个真实任务，收集他不满意的地方。你需要能画出数据流，解释为什么这样切分或校验、最可能失败在哪里、为什么没有选择更复杂的Agent。

## 这一阶段不是比谁的Demo更炫

真正的完成信号是：换一批资料或换一个工具，你仍能重建主要链路；回答或操作失败时，你知道去哪一层找原因；系统有少量但稳定的评测样本，而不是只展示最成功的几个问题。

负责人使用的任务编号、验收边界和证据映射见[阶段控制表](stage-control.md)。
