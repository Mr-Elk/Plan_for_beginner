# 14 项目控制与证据追溯

## 1. 目的

本文件把总体规划连接到日常执行，回答四个问题：

1. 项目当前处于什么状态？
2. 满足什么条件才能正式开训或晋级？
3. 每项判断使用什么定义一致的数据？
4. 从项目目标到任务、证据和决策能否双向追溯？

控制面的目标是减少模糊决策，不是建立复杂管理系统。没有决策用途的数据不收集，没有执行数据时不建设自动化仪表盘。

## 2. 项目结果链

```text
投入
→ 训练活动
→ 可检查产出
→ 独立能力证据
→ 阶段能力
→ 可交付项目与求职反馈
```

对应关系如下：

| 层级 | 单一事实源 | 核心问题 |
|---|---|---|
| 目标与边界 | 项目章程 | 为什么做、什么不做、怎样算成功？ |
| 能力要求 | 能力矩阵 | 需要形成哪些能力、达到什么等级？ |
| 顺序与范围 | 路线图、课程范围 | 先后依赖和深度边界是什么？ |
| 两周承诺 | 课程包 | 本周期交付什么、怎样验收？ |
| 执行证据 | 项目仓库、测试、考核、证据索引 | 实际发生了什么？ |
| 调整决策 | 周复盘、阶段报告、变更记录 | 根据证据保持、补修、暂停还是变更？ |

每个Must目标必须能向上追溯到一个能力和项目目标，向下追溯到至少一个验收证据。无法建立这两条关系的任务不进入当前课程包。

## 3. 运行状态

项目同一时间只处于一个主状态：

| 状态 | 含义 | 允许动作 | 退出条件 |
|---|---|---|---|
| 规划中 | 总体规则仍在治理 | 修改总体文档、设计启动门 | 总体基线获批 |
| 待启动 | 总体基线稳定，正在准备P0 | 创建诊断课程包、验收材料和环境冒烟测试 | 通过S0开训门 |
| 执行中 | 正在执行一个课程包 | 学习、开发、考核、复盘 | 课程包验收或风险升级 |
| 恢复中 | R2/R3或暂停新增被触发 | 缩小范围、补修、恢复验证 | 满足风险退出条件 |
| 阶段验收 | 汇总能力证据并决定晋级 | 未污染考核、答辩、证据审查 | 晋级、条件晋级或返回补修 |
| 完成/转向 | 达到毕业条件、主动暂停或改变方向 | 归档证据、总结结果、制定后续方案 | 新项目重新立项 |

路线图阶段描述能力重心，运行状态描述项目如何被控制，两者不能互相替代。

## 4. S0正式开训门

从“待启动”进入“执行中”前必须满足：

- [ ] 学习者与负责人确认项目章程、AI边界、证据规则和主要风险
- [ ] P0课程包有Must目标、当前能力入口、验收标准和明确非目标
- [ ] 无AI基线题、答案和私有测试与学习者及辅导AI完成访问隔离
- [ ] WSL2、Git、Python、依赖管理和密钥示例通过最小冒烟测试
- [ ] 第一周有效时间安排、休息边界和无法维持40小时时的降级方案已确认
- [ ] 负责人、辅导AI、验收者的角色和第一次周复盘时间已确定
- [ ] 证据索引已创建，能够链接代码、测试、考核和评审记录
- [ ] API/云服务预算边界、密钥存放方式和费用异常处理已确认

S0只有三种结论：

- 通过：可以正式执行P0
- 条件通过：只允许解决列出的启动阻塞，不开始正式教学计时
- 不通过：返回待启动，不用学习者加班弥补准备缺陷

S0与能力矩阵中的G0不是同一个门：S0发生在P0开始前，验证训练系统、课程包和考核是否准备好；G0发生在P0结束后，验证学习者是否已经形成环境、Git、基础编程和AI纪律证据。

## 5. 最小指标合同

指标必须先定义再收集，同一课程包内不临时改变口径。P0负责产生基线，不预先设定虚假精确目标。

| 指标 | 定义 | 原始来源 | 决策用途 |
|---|---|---|---|
| 有效学习时间 | 围绕批准目标进行，并留下代码、测试、解释、练习或决策产物的专注时间；休息、纯等待和未处理的被动观看不计 | 每日日志、Git、学习块 | 判断负荷和时间分布，不证明能力 |
| Must验收率 | 已达到验收标准的Must数量 ÷ 课程包开始时冻结的Must数量；批准删除的目标单独记录，不改写历史分母 | 课程包、验收记录 | 正常、条件或暂停新增 |
| 独立考核结果 | 在声明的A0、资料和时间边界内，按固定评分表得到的结果 | 考核产物、测试、评分依据 | 判断L2及以上能力 |
| 辅助差距 | 同一能力的有辅助代表任务与延迟A0/A1变式之间的表现差异；不比较难度明显不同的任务 | 练习、复测、评分表 | 决定撤除、保持或恢复支架 |
| 延迟保持 | 已安排复测的核心能力中，按期完成且仍通过的数量与失败原因 | 理论账本、复测任务 | 调整复习与重新教学 |
| 迁移证据 | 本周期产生的最高有效T1/T2/T3证据及其任务 | 证据索引、考核 | 判断L1/L2/L3晋级 |
| 学习债务 | 未解释AI代码、未验证结论、失败测试和待重建核心内容；按新增、清偿、逾期记录 | 日志、项目Issue | 控制是否允许开启新内容 |
| 可持续性 | 睡眠、精力、注意力和动机的简要趋势，以及是否触发R1–R3 | 周复盘 | 降载或启动恢复剧本 |
| 外部反馈闭环 | 辅导上下文之外的问题中，已澄清、接受/拒绝并说明理由、完成验证的数量 | Issue、PR、用户反馈 | 验证交接、协作和真实用途 |

规则：

- 完成时长、提交次数和代码行数只能解释过程，不能单独证明能力
- 缺失数据标记“缺失”，不能记为0，也不能由AI猜测补全
- 指标口径变化必须注明生效课程包，前后数据不直接比较
- 定量结果与错误原因、项目阻塞等定性证据一起解释
- 每周只审查会触发决定的指标，不为了完整填写所有可能字段

## 6. 证据索引

执行开始时复制 [证据索引模板](../templates/evidence-index.md)，为重要证据建立唯一入口。索引不复制完整内容，只链接原始产物。

每条证据至少包含：

- 证据ID、日期和课程包
- 对应能力、目标等级和迁移等级
- 原始产物链接或Git提交
- 最高AI等级和允许资料
- 评审人、结论、污染状态和复测条件

追溯必须可以双向回答：

```text
这个目标由哪些证据支持？
这条证据影响了哪个能力等级和哪次决定？
```

私有答案、隐藏测试和密钥不得进入索引；只记录受控位置、验证结论或负责人引用。

## 7. 决策输出

每次评审只产生一种主结论：

| 结论 | 含义 | 后续动作 |
|---|---|---|
| 正常前进 | Must、独立证据和风险满足当前要求 | 生成下一批任务，保持主要变量不变 |
| 条件前进 | 主线可继续，但有明确局部缺口 | 缺口绑定负责人、复测和截止条件 |
| 暂停新增 | 独立能力、债务、健康或证据可靠性失控 | 进入恢复中，只修核心缺口 |
| 晋级 | 阶段要求有足够、有效和新近的证据 | 更新能力矩阵，进入下一能力重心 |
| 转向/结束 | 目标、约束或外部条件发生重大变化 | 使用变更流程，归档原基线和证据 |

决定必须引用证据ID或风险记录。没有证据时可以保留现状或设计小实验，不能把主观确信写成已验证结论。

## 8. 执行目录约定

正式开训后建议增加：

```text
course-packs/       # 已批准的两周课程包
evidence/           # 证据索引，不存私有答案
reviews/            # 周复盘、阶段报告和恢复记录
```

学习项目可以使用独立Git仓库，在证据索引中链接。私有考核材料必须位于不同访问边界，不在本仓库用隐藏目录伪装隔离。

## 9. 控制面停止条件

满足以下条件后不再扩充项目控制规则：

1. 当前状态和下一状态明确。
2. S0可以决定是否正式开训。
3. 核心指标有统一定义、来源和决策用途。
4. 目标、能力、任务、证据和决定能够追溯。
5. 风险可以进入恢复流程并有退出条件。

下一步应使用P0真实数据校准指标，而不是预先增加权重、仪表盘、自动评分或更多状态。
