# 14 项目控制与追溯

本文件回答三件事：项目现在处于什么状态，开训与晋级需要什么证据，目标怎样追溯到执行产物。

## 1. 结果链

```text
项目目标
→ 能力门
→ 阶段任务
→ 阶段合同
→ 课程包和周任务
→ 代码、测试、考核与反馈
→ 评审决定
```

每个 Must 必须向上指向阶段任务和门条款，向下指向至少一个验收证据。指不清的任务不进入课程包。

## 2. 运行状态

| 状态 | 允许动作 | 退出条件 |
|---|---|---|
| 规划中 | 治理总体文件，准备 S0 | 总体基线获批 |
| 待启动 | 准备 P0 合同、课程包、环境和考核 | S0 通过 |
| 执行中 | 学习、开发、考核、复盘 | 课程包验收或风险升级 |
| 恢复中 | 停止新增，修复核心缺口 | 达到风险退出条件 |
| 阶段验收 | 汇总门证据、答辩和复测 | 晋级、条件晋级或补修 |
| 完成/转向 | 归档并制定后续方案 | 新目标重新立项 |

能力阶段 P0–P7 与运行状态不是一回事。例如项目可以处于“恢复中”，但仍属于 P2。

## 3. S0 正式开训门

开训前必须满足：

- 学习者与负责人确认章程、AI 边界和证据规则；
- P0 合同已批准，并映射 G0；
- 第一个课程包有 Must、验收和非目标；
- 私有答案、隐藏测试和评分材料已隔离；
- WSL、Git、Python、依赖和密钥通过冒烟测试；
- 40 小时安排及无法维持时的降级方案已确认；
- 负责人、辅导 AI、验收者和复盘时间明确；
- 证据索引已创建；
- API 与云服务预算、密钥和费用异常处理已确认。

S0 可判定为通过、条件通过或不通过。条件通过只允许处理启动阻塞，不能开始正式训练。S0 检查训练系统是否准备好；G0 检查学习者是否形成起步能力，两者不能混用。

## 4. 最小指标

| 指标 | 定义 | 用途 |
|---|---|---|
| 有效时间 | 围绕批准目标并留下产出的专注时间 | 判断负荷，不证明能力 |
| Must 验收率 | 通过的 Must ÷ 开包时冻结的 Must | 判断课程包结果 |
| 独立表现 | 在声明的 AI、资料和时间边界内的结果 | 判断 L2 以上能力 |
| 辅助差距 | 有辅助任务与延迟独立变式的差异 | 决定是否撤除支架 |
| 延迟保持 | 到期复测仍通过的核心能力 | 调整复习和补修 |
| 迁移证据 | 本周期最高有效 T1/T2/T3 | 判断能力升级 |
| 学习债务 | 未解释代码、未验证结论、失败测试等 | 控制是否新增内容 |
| 可持续性 | 睡眠、精力、注意力和动机趋势 | 决定降载或恢复 |
| 外部反馈 | 用户或评审提出并完成闭环的问题 | 验证真实使用与协作 |

口径在课程包开始时冻结。缺失数据标“缺失”，不记为 0，也不由 AI 猜测。

## 5. 证据索引

每条重要证据至少记录：证据 ID、日期、阶段与课程包、任务与门条款、目标能力、迁移等级、原始链接、最高 AI 等级、评审结论、污染状态和复测条件。

命名约定：

- 阶段任务：`ST-P0-01`
- 周任务：`WT-P0-W01-01`
- 课程包：`CP-P0-01`
- 周复盘：`WR-P0-W01`
- 阶段验收：`SR-P0`
- 证据：`E-P0-001`

私有答案和密钥不进入索引，只记录受控位置或验证结论。

## 6. 目录与生命周期

```text
stages/Px/
  README.md           学习者指南
  stage-control.md    全年任务积压
  stage-contract.md   当前阶段批准后创建
  course-packs/       两周课程包
  weeks/              周任务
  reviews/            周复盘与阶段验收
evidence/index.md     全局证据索引
```

未来阶段可以保留指南和控制表，但不能提前创建已批准合同、完成状态或预期证据。阶段合同记录纳入、合并、降级或删除了哪些阶段任务。

## 7. 评审结论

| 结论 | 后续动作 |
|---|---|
| 正常前进 | 生成下一批任务 |
| 条件前进 | 缺口绑定负责人、复测和期限 |
| 暂停新增 | 进入恢复，只修核心缺口 |
| 晋级 | 更新能力证据，进入下一主攻阶段 |
| 转向/结束 | 走变更流程并归档原基线 |

决定必须引用证据或风险记录。没有证据时可以保持现状或设计小实验，不能把判断写成已验证事实。
