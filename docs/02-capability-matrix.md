# 02 能力矩阵与晋级标准

## 1. 能力等级

| 等级 | 定义 | 可接受证据 |
|---|---|---|
| L0 未接触 | 不理解术语或无法开始 | 无 |
| L1 引导完成 | 在资料、提示或示例下完成 | 练习记录、解释笔记 |
| L2 独立应用 | 无答案、低 AI 辅助下完成常见任务 | 无 AI 考核、变式任务、Git 记录 |
| L3 工程交付 | 能处理异常、测试、文档、部署和取舍 | 完整项目、测试、部署、口头答辩 |
| L4 迁移与指导 | 能比较方案、迁移场景并指导他人 | 设计评审、复杂重构、公开技术输出 |

第一轮训练主要目标是：核心编程和后端达到 L3；数据、ML、前端和 LLM 原理达到 L2；LLM 应用交付达到 L3。L4 不是毕业要求。

矩阵表示各能力在阶段结束时的合理状态，不表示进入权限。能力可以提前以L1预览进入；阶段晋级仍只依据对应G门和有效证据，不能用其他能力的亮眼Demo补偿核心缺口。

## 3. 通用评分

每个阶段闯关按 100 分评分：

| 维度 | 权重 |
|---|---:|
| 问题定义与方案设计 | 10 |
| 项目功能与完成度 | 20 |
| 无 AI 编程考核 | 20 |
| 陌生需求修改 | 15 |
| 口头解释与原理 | 10 |
| 测试、错误处理与代码质量 | 15 |
| 文档、Git与部署 | 10 |

### 决策规则

- 80–100：通过，可进入下一阶段
- 65–79：条件通过，下一课程包必须携带补修项
- 0–64：未通过，只重做未达标能力，不机械重学整个阶段
- 项目可以运行但无法解释核心代码：最高只能条件通过
- 无 AI 考核无法独立开始：不通过该阶段核心编程能力
- 存在密钥泄露、伪造提交或隐瞒 AI 整体代写：本次项目证据无效

## 4. 阶段闯关证据

### G0 训练准备门

- 能在 WSL 中创建、运行和调试 Python 文件
- 能使用 Git 完成基本提交并说明改动
- 完成两个小程序和一次无 AI 基线测试
- 能遵守密钥和 AI 使用规则
- 形成真实的 40 小时执行数据

### G1 Python独立编程门

- 90 分钟内无 AI 完成一个未见过的小程序
- 能把自然语言需求写成输入、输出、规则和边界条件
- 能将需求拆成函数和模块
- 能正确使用基本容器和异常处理
- 能为核心逻辑补测试
- 能修改一个陌生变式而不是背原题

### G2 后端基础门

- 能把用户流程转成接口、数据模型和验收条件
- 能从零创建带数据库的 API
- 能解释请求、业务逻辑和持久化的数据流
- 能写常见 SQL、理解索引和事务的基本作用
- 能实现认证、输入校验和集成测试
- 能定位常见 HTTP 和数据库错误
- 能通过Issue/PR提交一个改动，并针对评审意见解释、修改或有依据地拒绝

### G3 端到端交付门

- 能说明目标用户、核心问题和明确不做的范围
- 用户可通过前端完成核心流程
- 应用可使用 Docker 在 Linux 环境运行
- 有基本权限边界、日志和 CI 测试
- 能处理文件、分页、错误和配置
- 能现场完成一个前后端需求修改
- 一个未参与实现的人能够仅依据README运行核心流程并提交问题反馈

### G4 ML闭环门

- 能判断问题是否真的需要机器学习，并给出简单基线
- 能检查数据并建立简单基线
- 正确划分训练、验证和测试数据
- 能选择并解释合适指标
- 能识别至少一种过拟合或数据泄漏风险
- 能部署一个推理接口并完成错误分析

### G5 LLM原型门

- 能判断规则、检索、传统ML或LLM哪种方案更合适
- 能不依赖复杂框架实现结构化输出或工具调用
- 能实现文档处理、检索和引用链路
- 能解释切分、召回和生成的主要失败模式
- 能建立最小评测集
- 能控制输入输出契约和基本错误处理

### G6 生产级AI门

- 有离线评测、人工检查和版本对比
- 有超时、重试、回退、日志和成本数据
- 有 Prompt Injection、权限和隐私边界
- 工具调用包含参数校验和必要的人工确认
- 能用证据说明一次优化是否有效

### G7 综合毕业门

- 旗舰项目满足章程中的作品要求
- 有真实或代理用户反馈及对应迭代记录
- 能进行 30 分钟项目答辩
- 能完成目标岗位基础编程和后端任务
- 能解释架构取舍、失败案例和未来改进
- 完成简历、项目介绍和试投递反馈复盘
- 至少完成一次来自导师以外的人类用户、开发者或面试官的评审—修改闭环

## 5. 证据可靠性顺序

从强到弱：

1. 无 AI 限时变式任务
2. 现场需求修改和调试
3. 自动测试、隐藏测试和部署结果
4. 口头答辩和代码走查
5. 可审计的 Git 提交过程
6. 日常练习完成记录
7. 视频观看、课程证书和自我感觉

低等级证据不能单独证明能力达标。

## 6. 通用迁移检查

任何能力从 L1 升到 L2 或更高，都至少需要一次迁移检查：

1. 更换数据、接口或业务背景，不复用原题文本。
2. 保留核心知识点，但改变至少一个约束或边界条件。
3. 学习者先说明旧方案哪些部分仍适用、哪些需要改变。
4. 完成后解释错误假设和替代方案。

重复原项目或背诵同类题不能单独证明迁移能力。

迁移距离使用 [质量与证据标准](07-quality-and-evidence.md) 中的T1–T3定义。L2晋级至少需要T2，L3晋级至少需要T3；不能用多个T1任务累加替代更远迁移。

## 7. 面试能力证据

面试准备是对已有能力的累计提取、迁移和表达，不单独证明技术能力，也不建立脱离项目的背题进度。

| 等级 | 表现 | 有效证据 |
|---|---|---|
| L1 | 在明确范围和提示下解释当前知识，完成准备过的短任务 | 当前主题口头检查、带边界的短编码 |
| L2 | 无完整答案完成代表性任务，能抽取历史知识并解释项目取舍 | 累计问答、限时变式、故障诊断、项目讲解 |
| L3 | 在混合且陌生的流程中澄清问题、实现或设计、解释权衡并根据反馈修正 | 综合模拟面试、外部面试官反馈、真实岗位任务 |

每个课程包的面试证据至少覆盖当期主攻能力；从P2开始还需抽取历史核心知识。一次回答正确不能单独使能力升级，必须能链接到代码、测试、项目、图示或可复查推理。

面试检查在G1–G6主要用于暴露对应能力缺口，不增加一套重复总分：如果失败来自Python、HTTP、SQL、ML或AI核心知识，则回到相应能力门处理；如果只是不熟悉表达或时间压力，则进入专项练习，不否定已有工程证据。G7要求在混合面试情境下形成L3证据。

AI可以生成问题、追问和反馈，但独立面试证据遵守A0边界；见过完整答案或评分锚点的问题只能用于练习，不能作为独立通过证据。
