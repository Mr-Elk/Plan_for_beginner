# 07 质量与证据标准

## 1. 开始条件

任务开始前至少明确：结果、输入输出、验收、AI 边界、时间盒和非目标。项目任务还要说明用户、主要失败路径和证据位置。

缺少前置知识时，把任务缩成可运行的最小切片；不要用模糊任务测试“悟性”。

## 2. 完成条件

### 练习

- 结果正确，并能解释关键步骤；
- 做过至少一个边界输入；
- 核心任务在规定 AI 边界内完成；
- 需要时完成一个改变约束的变式。

### 功能

- 验收场景通过；
- 正常与主要失败路径有测试；
- 错误能被记录或正确返回；
- 依赖、配置和运行方法可复现；
- 密钥、权限和数据边界已检查。

### 阶段项目

- 一个未参与实现的人能运行核心流程；
- 学习者能现场修改和调试；
- 证据可追溯到任务和能力门；
- 已知问题、取舍和未做范围写清；
- AI 项目另有固定样本、失败案例、延迟和费用记录。

## 3. 有效证据的六个属性

| 属性 | 要求 |
|---|---|
| 对应 | 能指向任务、能力和门条款 |
| 独立 | 声明 AI、资料和协助边界 |
| 可查 | 链接原始代码、测试、提交或录屏 |
| 新近 | 足以代表当前能力，过旧则复测 |
| 未污染 | 学习者未提前看到答案或评分锚点 |
| 可迁移 | 不只重复原示例 |

代码行数、提交次数、观看时长和证书只能说明过程，不能单独证明能力。

## 4. 迁移等级

| 等级 | 变化 | 例子 |
|---|---|---|
| T1 近迁移 | 换数据或名称，结构基本不变 | 把“待办”换成“售后工单” |
| T2 中迁移 | 改业务规则、边界或接口 | 工单增加优先级、权限和批量导入 |
| T3 远迁移 | 换场景并加入新约束，需要重新设计 | 从工单检索迁移到内部知识审批工具 |

L2 至少需要 T2；L3 至少需要 T3。多个 T1 不能相加代替更远迁移。

## 5. 独立考核

考核开始前固定：覆盖能力、题目难度、允许资料、AI 等级、时间、评分和污染处理。私有答案、隐藏测试和评分锚点与辅导上下文隔离。

若材料泄露：

1. 立即标记证据污染；
2. 原任务降为练习；
3. 重新生成等价但不同的任务；
4. 记录污染范围和新考核依据。

评分者对同一关键样例分歧明显时，先校准评分锚点，再评价学习者。

## 6. 项目质量等级

| 等级 | 表现 |
|---|---|
| Q0 | 只能在作者环境偶尔运行 |
| Q1 | 核心正常路径可运行，有最小说明 |
| Q2 | 有测试、错误处理、配置和重复部署 |
| Q3 | 有外部使用、观测、安全、恢复和取舍证据 |

阶段项目至少达到对应门要求；旗舰项目目标为 Q3。

## 7. 证据保留

重要证据登记到[证据索引](../templates/evidence-index.md)，索引只保存链接和结论，不复制整份产物。私有答案、真实密钥和敏感数据不得进入仓库。
