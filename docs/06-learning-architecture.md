# 06 学习架构

## 1. 目的

学习架构定义知识、练习、项目和考核如何形成能力。它不规定具体周数，解决的是“为什么学、先学什么、学到什么程度、如何迁移”的问题。

## 2. 五层能力结构

```text
识别问题与用户价值
        ↓
计算机与编程基础
        ↓
软件工程与交付能力
        ↓
数据、模型与AI应用能力
        ↓
验证、表达与市场迁移能力
```

### 问题与用户价值

- 用户是谁，真实痛点是什么
- 输入、输出、规则、约束和不确定性
- 怎样判断问题被解决
- 是否有比 AI 更简单可靠的方案

### 计算机与编程基础

- 把问题表达成数据、控制流、函数和模块
- 理解复杂度、状态、错误、文件、进程、网络和数据库
- 阅读报错、源码和官方文档

### 软件工程与交付

- 需求拆解、接口、数据模型和架构边界
- 测试、日志、配置、版本、部署和运维
- 安全、可靠性、协作和可维护性

### 数据与AI应用

- 数据质量、指标、基线和错误分析
- 模型能力边界和合适的技术选择
- 检索、工具、工作流、评测、成本和安全

### 验证与迁移

- 用测试、用户反馈和运行数据验证效果
- 在陌生场景中迁移知识
- 清楚表达决策、取舍、失败和改进
- 将能力映射到真实岗位或交付需求

任何课程包都不能长期只覆盖其中一层。

## 3. 学习单元契约

一个合格的学习单元必须包含：

1. 结果目标：完成后能做什么，而不只是知道什么。
2. 前置能力：开始前需要哪些知识和工具。
3. 最小解释：概念、用途、边界和一个反例。
4. 最小示例：可运行、可修改、不过度封装。
5. 引导练习：允许 A1–A2，强调过程。
6. 独立练习：使用相同知识解决不同表述的问题。
7. 项目迁移：把知识放入真实数据流或用户流程。
8. 验收证据：测试、变式、解释和提交记录。
9. 间隔复习：次日、数日后和后续项目中再次出现。

缺少结果目标、独立练习或验收证据的内容，只能作为参考资料，不能作为完整课程单元。

学习单元按 [高效学习步骤](13-efficient-learning-process.md) 执行：先预试暴露缺口，再精准输入；示例必须逐步淡出，最后以独立重建、变式迁移和间隔复测收尾。课程包定义“学什么和如何验收”，学习块负责“当下怎样学”。

## 4. 依赖规则

- 新任务最多依赖 1–2 个尚未达到 L2 的核心能力。
- 前置能力不足时，只补当前任务必需部分，不全面回炉。
- 同一个概念至少经历“理解、练习、项目使用、陌生变式”四次接触。
- 高层框架不能隐藏当前正在训练的核心过程。
- 当抽象阻碍理解时，先用显式代码实现，再引入封装。
- 当重复劳动不再产生理解收益时，允许使用工具或框架自动化。

## 5. 螺旋学习

同一能力应在不断扩大的场景中重复出现：

| 能力 | 第一次 | 第二次 | 第三次 | 工程化 |
|---|---|---|---|---|
| 数据持久化 | JSON文件 | SQLite | PostgreSQL | 迁移、索引、事务、备份 |
| 接口 | 函数输入输出 | CLI参数 | HTTP API | 鉴权、限流、版本和观测 |
| 测试 | 断言 | 单元测试 | 集成测试 | CI、回归和失败诊断 |
| AI输出 | 自由文本 | JSON结构 | 工具调用 | 契约、回退、评测和审计 |
| 检索 | 关键词搜索 | Embedding | 混合检索 | 重排、指标、引用和反馈 |

复现同一个例子不算新的螺旋层级；必须增加约束、责任或验证难度。

## 6. 项目层级

### 微型练习

- 目标：验证单个概念
- 规模：几十分钟到数小时
- 不要求部署和完整文档

### 技能项目

- 目标：组合 2–4 个能力
- 规模：数天
- 要求测试、README 和至少一个变式

### 阶段项目

- 目标：证明一个阶段的端到端能力
- 规模：跨多个课程包
- 要求用户流程、架构、测试、部署、答辩和复盘

### 旗舰项目

- 目标：证明能处理真实不确定性和工程责任
- 要求真实或代理用户反馈、质量指标、失败边界、安全、成本和迭代记录

项目数量服从证据质量。低质量项目不能通过增加数量弥补。

## 7. 项目工作流

正式项目按以下顺序推进：

```text
问题陈述
→ 用户与场景
→ 成功指标和非目标
→ 最小方案与替代方案
→ 数据和接口设计
→ 实现与测试
→ 部署与观测
→ 用户/代理反馈
→ 复盘与下一次迭代
```

禁止先选框架，再反向寻找问题。

## 8. 内容选择规则

一个知识点进入 Must，至少满足一项：

- 是后续多个核心能力的前置依赖
- 当前项目立即需要
- 是目标岗位反复要求的可迁移基础
- 能降低高概率、高影响风险

进入 Should 的内容应能明显提高质量、效率或理解。仅有趣、流行或可能将来使用的内容进入 Stretch 或知识候选池。

## 9. 学习自主性

训练不仅交付技术能力，也应逐步撤除外部脚手架：

- 初期：课程包明确任务、资料和验收
- 中期：学习者参与拆任务、选择资料和设计测试
- 后期：学习者提出问题、写设计、选择方案并申请评审
- 毕业：能够自行建立一个小型学习 LOOP，并说明何时停止学习、开始交付
