# 11 受控并行执行

并行的目的，是让项目、基础和复习互相提供反馈；不是同时开多门课。

## 1. 默认模型：1＋2

| 流 | 数量 | 作用 | 例子 |
|---|---:|---|---|
| 主交付流 | 1 | 当前唯一用户结果 | 完成售后工单查询 API |
| 基础支撑流 | 1 | 解决主项目正在暴露的缺口 | SQL 索引和事务练习 |
| 轻量巩固流 | 1 | 低切换成本的长期能力 | 算法复测、英语、项目讲解 |

同时进行的高认知任务最多两个；轻量巩固不应演变成第二主项目。

## 2. 可以并行的内容

- 写 API，同时练习它实际使用的 SQL。
- 做模型评测，同时复习对应统计指标。
- 项目等待外部反馈时，完成独立变式或文档修订。
- 每天短时算法、英语和历史知识提取。
- 负责人准备下一课程包，学习者继续当前课程包。

## 3. 不应并行的内容

- 同时开发两个大型项目。
- 同时学习 FastAPI、Django 和另一套后端框架。
- Python 基础尚不稳定时，同时系统学前端、后端和机器学习。
- 核心功能未跑通前加入多个 AI 能力。
- 同一个人边辅导边看私有答案并执行验收。

## 4. 依赖与切换

任务只有三种依赖：必须先完成、可以边做边补、可独立进行。课程包只把第一种写成硬阻塞。

切换前保存四项：当前结果、测试状态、下一步、已知阻塞。若一周出现多个半成品、重复重新理解上下文或主项目无增量，先关闭支撑任务，不再新增时间管理技巧。

## 5. 角色流水线

负责人和 AI 可以提前准备资料、测试设计和下一包草案，但不得把未批准草案当成学习者任务。验收材料由独立上下文保管；辅导 AI 只接收公开题面和允许反馈。

```text
负责人定义结果与边界
→ AI 生成公开讲解和练习草案
→ 负责人审查
→ 学习者执行并留下证据
→ 验收者独立检查
→ 负责人决定下一步
```

## 6. 失控信号

连续三天不能说清唯一主结果、WIP 超过三个、多个项目都停在“快完成”、或支撑学习与主项目没有连接时，立即回到一条主交付流。并行是否有效看交付和独立能力，不看每天接触了多少主题。
