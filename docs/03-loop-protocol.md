# 03 LOOP 执行协议

## 1. LOOP 的目的

LOOP 用于把路线图变成可反馈、可调整的训练过程。它不追求每天覆盖最多内容，而追求稳定产生能力证据。

```text
定义结果
→ 预试与独立首试
→ 诊断缺口
→ 精准输入
→ 独立重建
→ 变式与项目迁移
→ 验证讲解
→ 间隔复测
```

完整方法、分内容路径和退出条件见 [高效学习步骤](13-efficient-learning-process.md)。

## 2. 日循环

每个训练日按以下顺序执行：

1. 写下今日唯一主交付物和最多两个次目标。
2. 为当前学习块写清结果、验收和明确不学的内容。
3. 根据该能力当前L0–L3证据选择入口；L0做预测或识别型最小预试后进入示例，L1以上留下独立首试产物。
4. 判断主缺口属于概念、设计、语法/API、调试、前置知识还是环境/范围。
5. 只学习解决主缺口所需的最小资料，必要时按 [AI 辅助等级](04-ai-use-policy.md)逐级求助。
6. 使用最小例题时逐步撤除提示，然后关闭完整答案从空白独立重建。
7. 修改至少一个条件，并把知识放入当前项目的真实数据流。
8. 运行测试、检查失败路径并口头解释用途、边界和调试方法。
9. 提交 Git，使用 [每日日志模板](../templates/daily-log.md) 记录证据、最高 AI 等级、学习债务和下一步。
10. 将需要解释、迁移或复测的理论加入 [理论回顾账本](../templates/theory-review-ledger.md)，安排下一次无提示复测。

复杂或首次接触的主题使用 [单次学习块模板](../templates/learning-session.md)；简单任务可以只保留关键字段。

每日结束条件不是“坐满时间”，而是有代码、测试、解释或明确的问题记录。

### 日内并行边界

- 保持一个主交付物，不同时推进两个主功能
- 同一天最多处理两个高认知上下文，例如“Python项目＋算法”或“后端＋SQL”
- 第三条流只能是复习、文档、英语、代码阅读或错误回归
- 切换前必须记录当前状态、下一步和已知阻塞
- 长任务等待时使用预先准备的低切换清单，不临时开启新课程

## 3. 周循环

### 周一：计划

- 从当前两周课程包选择本周 Must 目标
- 将目标拆成可验收的交付物
- 估算时间并预留 20% 缓冲
- 明确周考内容和禁止使用的辅助
- 为本周指定一条主交付流、一条基础支撑流和一条轻量巩固流
- 检查WIP是否符合 [受控并行执行模型](11-parallel-execution.md)

### 周二至周四：学习与开发

- 完成知识块和递进练习
- 将知识应用到主项目
- 每天至少一次“首试—精准输入—独立重建”闭环
- 持续补测试、日志和文档

### 周五：集成与重构

- 合并本周功能
- 修复测试和边界条件
- 删除临时代码和硬编码秘密
- 完成一次代码走查和口头解释

### 周六：演示与考核

- 演示本周可运行成果
- 考核前预测得分、完成时间和主要风险，考核后比较偏差
- 完成无 AI 任务
- 完成一个陌生变式或现场修改
- 记录成绩、失败点和证据链接

### 周日半天：复盘

- 使用 [周复盘模板](../templates/weekly-review.md)
- 分类错误：知识、设计、语法、调试、工具、注意力或 AI 依赖
- 决定下周继续、补修或降载
- 只安排轻量复习，不引入大型新主题

## 4. 六周循环

- 第 1–4 周：学习、练习、主项目迭代
- 第 5 周：阶段整合和项目交付
- 第 6 周：少引入新知识，集中补缺、重构、复习和综合考核

第 6 周仍可保持 40 小时，但高认知负荷内容下降，时间转向测试、阅读、文档、演示和修复。

周期结束必须回答：

1. 哪些能力有可靠证据？
2. 哪些内容只是“看懂”但不能独立完成？
3. AI 辅助等级是否在上升？
4. 40 小时中真正用于编码、思考和复盘的比例是多少？
5. 下一周期最多调整哪三个项目？
6. 有辅助练习与延迟独立任务的差距是在缩小还是扩大？
7. 本周期是否获得了辅导上下文之外的用户或评审反馈？

## 5. 40 小时参考预算

| 类型 | 每周参考 |
|---|---:|
| 项目与编码 | 18 小时 |
| 编程与工程知识 | 8 小时 |
| 数据结构与算法 | 4 小时 |
| 数学或AI原理 | 3 小时 |
| 官方文档与技术英语 | 3 小时 |
| 测试、重构和安全检查 | 2 小时 |
| 周考与复盘 | 2 小时 |

建议节奏：周一至周五每天约 6.5 小时，周六约 5 小时，周日约 2.5 小时。单日真正高强度编码通常不超过 4–5 小时，其余用于阅读、测试、解释和整理。

## 6. 调整规则

### 正常前进

- Must 完成率至少 80%
- 无 AI 考核达到阶段要求
- 没有无法解释的核心代码
- 连续疲劳和注意力问题未恶化

### 条件前进

- 总体得分 65–79
- 主要项目可以继续，但存在 1–3 个明确能力缺口
- 下一课程包为每个缺口安排一个补修任务和一次复测

### 暂停新增内容

满足任一条件时，暂停增加框架或新主题：

- 连续两周 Must 完成率低于 70%
- 无 AI 任务无法独立开始
- 项目核心代码无法解释
- 测试长期缺失或错误反复出现
- AI 帮助持续处于 A3–A4

暂停时只修复核心缺口，不整体推倒重来。

### 加速

连续两周达到以下条件才能加速：

- Must 全部完成
- 无 AI 变式任务得分至少 85
- 项目测试和文档完整
- 仍有稳定休息和复盘

加速优先增加 Stretch 任务或项目深度，不同时引入多个新框架。

## 7. 执行数据

每周至少记录：

- 有效学习时间及类别
- Must/Should/Stretch 完成率
- Git 提交和项目证据
- 无 AI 考核成绩
- 最高 AI 辅助等级分布
- 辅助练习与延迟独立任务的表现差距
- 主要 Bug 和错误类别
- 睡眠、疲劳和注意力的简要主观评分
- 下周补修与风险

这些数据用于调整课程包，不用于制造虚假的精确绩效。
