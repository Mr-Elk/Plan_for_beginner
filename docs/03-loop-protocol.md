# 03 执行节奏

本文件只规定日、周、两周和六周节奏。单个知识点怎样学，见[高效学习流程](13-efficient-learning-process.md)。

## 1. 每周 40 小时怎样分

建议起点如下，执行两周后按证据调整：

| 工作 | 小时 | 说明 |
|---|---:|---|
| 主项目纵向切片 | 20 | 当前唯一交付物 |
| 必要基础 | 8 | Python、HTTP、SQL、测试等当前阻塞项 |
| 算法与计算机基础 | 5 | 精选题、故障解释、历史复测 |
| AI、数据或数学 | 3 | 只学当前阶段需要的部分 |
| 官方文档与技术英语 | 2 | 围绕正在做的任务 |
| 独立检查与复盘 | 2 | 无答案任务、证据整理、下周决定 |

这不是打卡配额。项目暴露基础缺口时可以临时调整，但总 WIP 不增加。

## 2. 每日节奏

每天至少完成一个可检查结果：代码、测试、故障复现、图示、变式或评审结论。

```text
确认当天唯一结果
→ 先做一次独立尝试
→ 补最小知识
→ 完成并验证项目增量
→ 提交 Git
→ 记录卡点、AI 等级和明日第一步
```

一天结束时只回答四个问题：做成了什么、证据在哪里、哪里仍不懂、明天从哪一步开始。使用[每日日志模板](../templates/daily-log.md)。

## 3. 每周节奏

- 周初：从课程包选出本周唯一主交付物，冻结 Must。
- 周中：检查能否形成端到端增量；不能时立即缩小切片。
- 周末：演示、独立变式、抽取历史知识、分析错误和负荷。
- 复盘：只决定保持、补修、暂停新增或调整最多三项。

每周独立检查不固定成“刷题考试”。可轮换限时编码、SQL、故障诊断、接口设计和项目讲解，但必须声明 AI 与资料边界。

## 4. 两周课程包

每个课程包必须有：

- 一个用户可观察的主结果；
- 明确的 Must、Should、Stretch；
- 一个当前基础缺口；
- 一个独立重建或陌生变式；
- 正常路径与主要失败路径测试；
- 演示、证据链接和下一包决定。

第二周结束只做四类结论：通过、条件通过、补修或触发阶段验收。课程包不能修改阶段门。

## 5. 六周复盘

六周复盘看趋势，不重写每周细节：

1. 独立能力和 AI 辅助差距是否改善？
2. 项目是否持续产生端到端成果？
3. 哪类错误反复出现？
4. 40 小时负荷是否可持续？
5. 岗位和外部反馈是否要求调整优先级？

没有新证据时，不因为“感觉路线不够完整”而改总体规划。

## 6. 有效时间

有效时间必须围绕已批准目标，并留下可检查结果。休息、纯等待、无目的刷视频和重复试错不计。时间用于判断负荷，不用于证明能力。
