# 01 路线图

这份路线图只规定八个能力阶段。周数是参考窗口，G0–G7 才是晋级条件。各阶段并非八门串行课程：项目交付是主线，基础、算法、理论、英语和面试持续穿插。

## 1. 阶段总览

| 阶段 | 参考周数 | 主要问题 | 交付物 | 能力门 |
|---|---:|---|---|---|
| [P0](../stages/P0/README.md) | 1–2 | 能否安全、稳定地开始训练？ | 普通 CLI、模型 CLI、起点诊断 | G0 |
| [P1](../stages/P1/README.md) | 3–8 | 能否独立写出有用的 Python 程序？ | 有持久化、测试和 AI 功能的工具 | G1 |
| [P2](../stages/P2/README.md) | 9–16 | 能否把工具做成可靠的后端服务？ | 带认证、数据库和部署的 AI API | G2 |
| [P3](../stages/P3/README.md) | 17–24 | 能否让别人真正使用产品？ | 可登录、可部署的 AI Web 产品 | G3 |
| [P4](../stages/P4/README.md) | 25–30 | 能否用数据判断是否需要模型？ | 有基线、指标和错误分析的 ML 应用 | G4 |
| [P5](../stages/P5/README.md) | 31–38 | 能否让 AI 查到资料或安全调用工具？ | RAG 或工具工作流 | G5 |
| [P6](../stages/P6/README.md) | 39–44 | 系统失败时能否发现、控制和恢复？ | 对既有项目的生产级重构 | G6 |
| [P7](../stages/P7/README.md) | 45–48 | 能否把能力转成可信的求职证据？ | 旗舰项目、答辩、简历和投递复盘 | G7 |

## 2. 项目怎样成长

以“小型电商售后与知识助手”为例：

| 阶段 | 项目新增的真实能力 | 同时补的基础 |
|---|---|---|
| P0 | 从文本生成一份售后摘要 | 终端、Git、Python、密钥 |
| P1 | 保存、查询工单，并让模型输出固定结构 | 函数、容器、异常、测试、复杂度 |
| P2 | 客服通过 API 管理工单和调用模型 | HTTP、SQL、认证、日志、Linux |
| P3 | 客服通过网页完成核心流程 | React 核心、权限、Docker、CI |
| P4 | 判断工单类型或优先级 | 数据质量、统计、指标、PyTorch |
| P5 | 检索售后规则，或在确认后执行受控操作 | Embedding、召回、工具契约、评测 |
| P6 | 处理超时、越权、错误回答和费用异常 | 观测、回退、安全、成本 |
| P7 | 面向岗位收敛并接受外部检查 | 综合面试、项目表达、市场反馈 |

同一时间只推进一个主项目和一个主功能。项目可以换题材，但不要为了展示技术而并行开多个 Demo。

## 3. 贯穿八个阶段的内容

- 数据结构与算法：从 P0 诊断开始，围绕项目选择和限时变式持续训练。
- 计算机基础：在终端、HTTP、数据库、部署和故障中逐步补齐。
- 数学：遇到数据、模型和评测问题时即时复习，不先重学完整教材。
- 技术英语：每周阅读一小段当前任务需要的官方文档，并用运行结果验证。
- 测试与调试：从第一个 CLI 开始，不等到“学完框架”再补。
- 面试：每周抽取当期知识，从 P2 开始混入历史核心知识；P7 才集中收敛。
- AI 纪律：记录最高辅助等级，定期关闭答案重建和做陌生变式。

## 4. 每个阶段怎样落地

```text
阅读阶段指南
→ 负责人从阶段控制表选择任务
→ 批准当前阶段合同
→ 每两周生成一个课程包
→ 每周检查交付、独立能力和风险
→ 汇总能力门证据
→ 晋级、条件晋级或补修
```

阶段指南告诉学习者“要做成什么”；`stage-control.md` 保存任务 ID 和门映射；阶段合同才是当前阶段的正式承诺。未来阶段不提前生成周任务。

## 5. 时间偏差怎样处理

- 提前完成：增加陌生变式、质量或真实用户反馈，不另开框架。
- 进度落后：先删除 Should 和 Stretch，再缩小项目切片。
- 核心证据不足：只补对应缺口，不机械重学整个阶段。
- 连续两周负荷异常：进入恢复流程，重新估算 40 小时可持续性。
