# 01 48 周路线图

## 1. 路线图规则

- 路线图提供推荐顺序，不代替能力验收。
- 每两周只生成一个课程包，避免过早细化全年日程。
- 每六周进行一次周期复盘，必要时调整后续阶段，不随意改动培养目标。
- 数据结构、算法、计算机基础、技术英语、表达和 AI 纪律贯穿全年。
- 正式 LLM 工程集中在后期，但早期安排低成本 AI 预览项目保持目标感。
- 阶段表示当前能力重心，不表示其他能力完全暂停；贯穿内容按 [受控并行执行模型](11-parallel-execution.md) 运行。

## 3. 各阶段边界

### P0 诊断与环境：第 1–2 周

目标：验证学习强度和基础能力，建立不会随课程变化而失效的工作方式。

必修内容：

- WSL2、终端、目录、文件和权限基础
- Git 基础、提交规范和项目 README
- Python 变量、条件、循环、函数和基本容器
- 报错阅读、最小化复现、调试记录
- `uv` 项目环境
- `.env`、`.gitignore` 和密钥安全
- AI 辅助等级和学习记录

产出：两个小型 CLI 程序、一次无 AI 基线考核、一份诊断报告。

### P1 Python基本功：第 3–8 周

目标：能够独立把需求拆成函数、数据结构、模块和测试。

必修内容：

- 函数、作用域、模块、异常、文件、JSON
- 类与对象的必要部分
- 类型标注和基础代码规范
- pytest、日志和调试
- 数组、哈希表、栈、队列、链表、树的基础概念
- 复杂度、排序、二分、递归和遍历

项目：可实际使用的 CLI 工具，必须包含持久化、搜索、异常处理、测试和文档。

### P2 后端基础：第 9–16 周

目标：理解一次 Web 请求如何穿过接口、业务逻辑和数据库。

必修内容：

- HTTP、JSON、REST、状态码
- SQL、表关系、索引、事务
- FastAPI、Pydantic、依赖和错误处理
- 数据库迁移、配置、日志、测试
- 基础认证和权限
- 异步编程的必要概念

项目：带数据库和认证的 API 服务，必须有集成测试和 API 文档。

### P3 生产级Web：第 17–24 周

目标：把后端服务变成用户可访问、可部署、可维护的完整产品。

必修内容：

- HTML、CSS、JavaScript、React 日常核心概念
- 文件上传、搜索、分页、流式响应
- 登录、角色和权限边界
- Docker、Linux部署、反向代理和 HTTPS 概念
- CI 自动测试、结构化日志、基本监控
- 重试、限流、缓存和后台任务的适用场景

项目：一个在线全栈系统。前端以清晰可用为目标，不追求复杂视觉工程。

### P4 数据与ML：第 25–30 周

目标：能够完成从数据检查到训练、评估、部署的基本机器学习闭环。

必修内容：

- NumPy、Pandas、数据清洗和可视化
- 向量、矩阵、导数、概率和统计的应用型复习
- 训练、验证、测试与数据泄漏
- 回归、分类、聚类的基本使用边界
- 准确率、精确率、召回率、F1和混淆矩阵
- PyTorch张量、自动求导、训练循环和模型保存
- Token、Embedding、Attention和Transformer概念

项目：一个有数据说明、基线、指标、错误分析和推理接口的 ML 应用。

### P5 LLM应用原型：第 31–38 周

目标：不依赖复杂框架，理解并实现常见 LLM 应用结构。

必修内容：

- 模型 API、流式输出、结构化输出
- Prompt 设计、版本和输入输出契约
- 工具调用及参数校验
- Embedding、切分、召回、重排和引用
- 对话状态和有限记忆
- RAG 和工作流式 Agent
- 本地模型推理体验

项目：一个带引用的知识库系统和一个带真实工具的工作流助手。

### P6 生产级AI：第 39–44 周

目标：把“能演示”升级为“可测试、可观测、可控制”。

必修内容：

- 评测数据集、离线评测和人工评测
- 检索指标、答案正确性和引用检查
- 超时、重试、回退、缓存和预算控制
- Tracing、Token、延迟和成本统计
- Prompt Injection、数据泄漏和工具权限
- 人工确认、审计日志和失败恢复
- 模型或供应商变化下的稳定接口

项目：对 P5 的一个项目进行生产级重构，并提供前后评测对比。

### P7 旗舰项目与求职：第 45–48 周

目标：用一个完整工程证明能力，并能在面试中解释。

产出要求：

- 在线演示、源代码、自动测试和部署说明
- 架构图、数据流、威胁与失败边界
- 评测集、指标、成本和性能说明
- 演示视频、技术复盘和未来改进
- 简历、项目介绍、常见问答和模拟面试记录

| 周 | 预览成果 | 目的 |
|---:|---|---|
| 4 | Python CLI 调用模型 | 建立目标感，不考察工程深度 |

预览成果不自动计入阶段闯关，除非同时满足该阶段的独立能力要求。

## 5. 贯穿式训练

### 数据结构与算法

- P0–P1：每周 4–5 小时
- P2–P3：每周约 3 小时
- P4–P7：每周约 2 小时
- 全年参考量：100–140 道精选题，重点是变式、解释和复杂度

### 技术英语

- 每个训练日约 30 分钟
- 主任务是阅读当前项目所需的官方文档和报错
- 允许翻译辅助，但需要用中文复述结论

### 求职反馈

- 第 8 周：建立公开项目说明标准
- 第 16 周：收集并分析目标岗位技能
- 第 24 周：完成一次模拟企业任务
- 第 30 周：根据岗位样本修订后半程
- 第 32 周：开始项目讲解和模拟面试
- 第 36 周：少量真实投递，收集反馈
- 第 40 周后：持续投递并针对性补强

岗位样本变化只影响课程优先级，不轻易改变项目章程中的主方向。
