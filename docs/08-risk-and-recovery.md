# 08 风险与恢复

风险处理的目标是恢复学习闭环，不是追责。先缩小范围和修复系统，再决定是否补时间。

## 1. 风险等级

| 等级 | 含义 | 动作 |
|---|---|---|
| R1 | 一周内可纠正的偏差 | 下周调整一到三项 |
| R2 | 连续两周影响交付或独立能力 | 暂停新增，进入补修 |
| R3 | 健康、安全、证据或方向失效 | 停止当前计划，负责人重新评审 |

## 2. 常见风险剧本

| 风险 | 早期信号 | 第一动作 | 恢复条件 |
|---|---|---|---|
| 40 小时不可持续 | 两周低于计划 70%，精力持续下降 | 删除 Should/Stretch，重排深浅任务 | 两周内负荷和 Must 稳定 |
| AI 依赖 | 无 AI 无法开始，不能解释代码 | 降到 A1，关闭答案重写，小步变式 | 延迟独立任务恢复 |
| 资源过载 | 同时跟多门课，收藏多于产出 | 每个主题只留一个主资料和官方文档 | 项目重新产生增量 |
| 基础阻塞项目 | 同类 Python/SQL/HTTP 错误反复出现 | 建立最小复现和专项技能任务 | 在项目和陌生变式中通过 |
| 项目膨胀 | 多个主功能并行，连续无演示 | 冻结新功能，只留一个用户动作 | 两周内形成可演示切片 |
| 环境阻塞 | 安装和配置占用大量时间 | 保存复现，使用临时替代环境 | 根因修复并写成可重复步骤 |
| 评估污染 | 答案、隐藏测试进入辅导上下文 | 废止相关证据，隔离并换题 | 等价新任务独立完成 |
| 密钥、数据或费用风险 | 密钥入库、费用异常、敏感数据外发 | 立即停用、轮换、止损并记录范围 | 边界修复并完成复查 |
| 动机下降 | 拖延、频繁换方向、看不到成果 | 缩短反馈周期，交付一个可见小结果 | 连续两周恢复执行 |
| 封闭误判 | 只有负责人和共享 AI 认为项目很好 | 引入冷启动用户或外部评审 | 完成评审—修改—再验证 |
| 就业方向偏差 | 岗位样本与训练能力持续不匹配 | 采样同类岗位并映射能力缺口 | 有证据地调整课程优先级 |

## 3. 恢复顺序

```text
停止新增
→ 确认风险等级和影响范围
→ 保留当前有效成果
→ 选择一个最小修复任务
→ 设计复测
→ 达到退出条件后恢复主线
```

R2/R3 期间不靠延长工作日维持表面进度。若健康、安全或证据真实性受影响，必须先处理根因。

## 4. 恢复记录

每次只记录：触发证据、风险等级、暂停内容、保持内容、修复任务、复测和退出条件。使用周复盘即可，不另建复杂风险系统。
