# 13 高效学习步骤

## 1. 高效的定义

高效不是单位时间看更多内容，而是用更少的无效输入，尽快形成可靠、可保持、可迁移的独立能力。

判断顺序是：

```text
能独立开始
→ 能完成代表性任务
→ 隔一段时间仍能复现
→ 换场景能够迁移
→ 能解释、调试和维护
```

只提高观看速度、代码行数或AI生成速度，不属于学习效率提升。

## 2. 根据当前能力选择入口

同一个学习者对不同能力可能处于不同等级。入口按“这项能力的当前证据”选择，不按年龄、阶段或总体印象选择。

| 当前状态 | 推荐入口 | 训练顺序 | 何时升级 |
|---|---|---|---|
| L0 无基本模型 | 极短预试后进入最小示例 | 预测关键步骤 → 逐行解释示例 → 补全缺口 → 独立重建 | 能解释并补全主要步骤 |
| L1 可引导完成 | 预试和局部首试 | 首试 → 精准输入 → 例题淡出 → 独立重建 | 能从空白完成代表性任务 |
| L2 可独立完成常规任务 | 直接进入变式或项目 | 陌生约束 → 调试 → 方案比较 → 间隔复测 | 能稳定迁移并处理主要边界 |
| L3 可工程交付 | 真实约束和协作交接 | 用户反馈 → 评审 → 性能/安全取舍 → 维护迭代 | 能在新场景中负责结果并帮助他人 |

L0 的“预试”可以只是预测输出、给代码排序或指出看不懂的部分，不要求零基础学习者长时间盲解完整任务。随着能力提高，完整示例应减少，独立问题和真实约束应增加。

### 实践出发还是知识点出发

本项目默认采用“实践牵引、知识回流”，不在纯实践和纯知识之间二选一。如果缺少入口判断，零基础学习者容易长时间盲解；如果始终先学完知识体系，又容易停留在看懂而不能交付。

```text
可验证的小任务
→ 预试或独立首试
→ 暴露主缺口
→ 最小必要知识
→ 关闭答案独立重建
→ 变式与项目迁移
→ 验证、讲解与延迟复测
```

具体入口按当前证据决定：

| 当前情况 | 起点 | 限制 | 转入下一步的信号 |
|---|---|---|---|
| L0，连任务中的基本对象和操作都无法识别 | 最小概念和带解释示例 | 只讲当前小任务所需的前置，不展开完整章节 | 能预测、补全并解释主要步骤 |
| L0–L1，能理解输入、输出和基本规则 | 有边界的微型任务 | 先留下预测、伪代码、失败代码或报错 | 能指出一个具体主缺口 |
| L1–L2，已有基本模型 | 独立首试或项目切片 | 失败后只补主缺口，不因一个 Bug 重学整章 | 能关闭答案重建并完成变式 |
| 同类错误重复、只会试错或无法解释 | 理论回流 | 从最小复现回到原理、反例和边界 | 能解释根因、补回归测试并在陌生小任务中复现 |
| 密钥、权限、费用或版本敏感操作 | 先学习必要规则并核对官方资料 | 不用不可逆或高风险试错代替学习 | 能在安全边界内完成最小操作并验证结果 |

这里的“实践”是微型任务或端到端小切片，不是让新手直接承担超出当前能力的大项目。“知识”是解决当前缺口所需的概念、反例和官方资料，不是预先学完整理论体系。课程包应以可验证输出为主，实践与输入的具体比例由 P0 数据和任务难度校准，不预设为能力结论。

## 3. 标准十步循环

### 第1步：定义结果

开始前写清楚：

- 完成后具体能做什么
- 输入、输出和主要约束
- 怎样验收
- 本次不学什么

目标使用“实现、解释、调试、比较、修改”等可观察动词，不只写“了解、熟悉”。

### 第2步：检索与预试

在看新资料前，先尝试从记忆回答或完成一个最小任务：

- 写出已有理解
- 画数据流或伪代码
- 预测程序输出
- 尝试一个最小实现
- 列出确定和不确定的部分

预试不是为了立即答对，而是激活已有知识并暴露真实缺口。如果已经会做，跳过重复教学，直接进入变式或项目。

### 第3步：独立首试

关闭AI和完整答案，完成一次诚实尝试。至少留下一个可检查产物：

- 需求重述
- 伪代码或接口草图
- 最小代码
- 失败测试
- 报错与已尝试方法

没有首试产物，不进入AI求助。

首试不是比拼卡住时长。只要已经形成可检查产物并能指出缺少的具体信息，就可以进入诊断；如果尝试仍在产生新假设或新证据，则继续独立推进。

### 第4步：诊断缺口

把卡点分到一个主要类别：

- 概念不知道
- 知道概念但不会设计
- 设计正确但语法/API不熟
- 代码能写但不会调试
- 缺少前置知识
- 注意力、环境或任务范围问题

一次只处理主缺口，避免因为一个Bug重学整章。

### 第5步：精准输入

只学习解决当前缺口所需的最小资料：

1. 主教材指定范围
2. 官方文档对应部分
3. AI的A1解释或A2方向

阅读时带着具体问题，不从头漫游。能通过文档查到的API细节不要求全部背诵。

### 第6步：例题淡出

新手可以先看一个最小正确示例，但脚手架要快速撤除：

```text
看懂并逐行解释
→ 补全缺失部分
→ 关闭资料从零重建
→ 修改条件
→ 放入项目
```

只完成“跟着敲一遍”不算掌握。

### 第7步：独立重建

关闭示例和AI，从空白文件、空函数或空白纸重新实现核心过程。

重建时允许查语言/API文档，但不查看同题完整解法。无法重建的部分回到第4步重新诊断，不重复观看全部内容。

### 第8步：变式与项目迁移

至少改变一个条件：

- 输入格式或数据规模
- 错误和边界条件
- 存储方式或接口
- 性能、安全或用户约束
- 业务场景

然后把知识放入当前项目的真实数据流。原题复现证明记忆，变式和项目才证明迁移。

### 第9步：验证与讲解

使用多类证据验证：

- 自动测试和失败路径
- 无AI或低辅助变式
- 口头讲解或画图
- 定位并修复一个Bug
- 对比替代方案和取舍

讲解至少回答：它解决什么问题、为什么这样做、什么时候不适用、失败时如何检查。

### 第10步：记录与安排复测

只记录影响下一步的信息：

- 产出和证据
- 最高AI等级
- 关键错误和理论缺口
- 当前掌握状态
- 下一次回忆、变式或项目复现

使用 [每日日志](../templates/daily-log.md) 和 [理论回顾账本](../templates/theory-review-ledger.md)，不写无决策用途的长篇流水账。

### 三层闭环

同一方法在不同时间尺度上重复，但不重复收集相同记录：

| 层级 | 核心闭环 | 必要产物 | 产生的决定 |
|---|---|---|---|
| 单次学习块 | 结果 → 首试 → 补缺 → 重建 → 变式 → 验证 | 代码、测试、解释或明确问题记录 | 继续当前任务、返回补缺或安排复测 |
| 每周 | 主线增量 → 集成与走查 → 无AI/低辅助变式 → 复盘 | 可运行增量、独立结果、错误分类和下周补修 | 正常前进、带补修前进或暂停新增 |
| 每两周课程包 | 冻结Must → 交付项目切片 → 演示与证据审查 → 调整下一包 | 课程包产物、证据ID、迁移结果和风险记录 | 保持节奏、局部补修、降载或进入阶段验收 |

周层的时序和阈值以 [LOOP 执行协议](03-loop-protocol.md) 为准；双周层的目标、AI边界和验收证据由 [课程包模板](../templates/course-package.md) 冻结。

## 4. 四阶段记忆巩固

### 获取

通过预试、最小解释和例题建立第一版理解。

### 重建

关闭答案，从记忆重新写、画或讲。重读不能代替重建。

### 间隔检索

在遗忘开始后再次回忆，不先看笔记。具体间隔由课程包根据难度设置，通常包含较近复测、数日后变式和后续项目复现。

### 迁移

在不同数据、接口、约束或业务场景中使用。只有原题记忆而没有迁移的知识，状态保持“待迁移”。

### 练习编排

- 新能力先用少量同类练习集中建立基本模型，不一开始就随机混合大量题型
- 首次达到独立正确后，将新题与相关旧题交错，训练识别“该用什么”而不只是重复步骤
- 后续优先让旧能力在项目中自然复现，只有反复遗忘时才增加专项练习

## 5. 不同内容的最短路径

### 语法和API

```text
明确要实现的功能
→ 查官方文档最小范围
→ 写最小调用
→ 处理一个错误情况
→ 放入项目
→ 记录非显然用法，不背完整API
```

重点是会查、会用、会验证，不是记住所有参数。

### 数据结构与算法

```text
重述问题和样例
→ 写朴素方案
→ 分析瓶颈
→ 使用分级提示
→ 完成并解释复杂度
→ 关闭答案重写
→ 做一个改变约束的变式
```

看答案后立即觉得理解，不算完成。

### 数学与理论概念

```text
从当前问题出发
→ 建立直觉和图示
→ 理解必要符号/公式
→ 用小数据手算或代码验证
→ 解释反例和适用边界
→ 回到模型或项目
```

公式推导深度服务于应用目标，不追求无边界完整性。

### 框架与工程能力

```text
一个用户流程
→ 官方最小示例
→ 一个端到端垂直切片
→ 测试和错误处理
→ 配置、日志与部署
→ 修改需求并重构
```

避免先系统学习框架全部功能，再开始项目。

### LLM与AI应用

```text
定义输入输出契约和基线
→ 最小模型调用
→ 保存失败样本
→ 结构化输出/工具/检索
→ 建立小型评测集
→ 优化质量、延迟和成本
→ 增加安全、权限和回退
```

AI应用的学习证据是评测和失败改进，不是“模型回答看起来不错”。

## 6. AI提示阶梯

AI求助按最小必要级别升级：

1. 学习者提交问题重述、已有尝试和具体卡点。
2. A1只给一个方向、检查问题或相关概念。
3. 再次尝试后仍无进展，A2比较方案或定位区域。
4. A3局部代码只用于跨过非核心阻塞，随后必须解释、测试和重写。
5. A4完整实现只作为研究材料，不产生独立能力证据。

AI第一次回复不应直接给完整答案；优先检查学习者是否真正理解问题。

## 7. 卡住时的决策

卡住不是坚持越久越好，也不是立即问AI：

- 需求不清：重写输入、输出、样例和非目标
- 缺概念：学习最小前置知识
- 缺设计：画数据流、拆函数、先写测试
- 缺语法/API：查官方文档和最小示例
- 调试困难：最小化复现，观察变量和错误边界
- 环境阻塞：记录复现，使用临时替代方案后另开修复任务
- 范围过大：缩成一个端到端切片

求助前必须能回答“我预期什么、实际发生什么、已经试过什么”。

是否继续独立尝试由信息增量决定：仍在产生新假设、新观测或更小复现时继续；连续重复相同操作、没有新证据时，停止盲试并回到缺口诊断或请求A1提示。

## 8. 掌握与退出条件

达到当前目标等级后就停止继续深挖，进入后续项目自然复现。

### L1引导完成

- 能跟随资料完成，并解释主要步骤

### L2独立应用

- 能从空白开始完成代表性任务
- 能处理主要边界并完成一个陌生变式
- AI保持A0–A1或只用于非核心查证

### L3工程交付

- 能设计、测试、部署和维护
- 能处理失败、安全和取舍
- 能根据反馈迭代

非核心知识达到L2通常足够；核心交付能力才追求L3。不要把所有主题都学到专家深度。

## 9. 学习债务

以下内容属于学习债务：

- 无法解释的复制代码
- 未验证的AI结论
- 只看答案、没有重建的练习
- 跳过的失败测试和边界条件
- 反复出现但未回到理论的Bug
- 长期停留“待应用/待迁移”的核心概念

学习债务可以短期存在，但必须有负责人、下一步和复测条件。A3/A4债务、失败测试和安全问题优先于开启新主题。

## 10. 效率信号

只观察少量能指导决策的信号：

- 独立首试能否开始
- 最高AI辅助等级是否下降
- 辅助练习与延迟无AI任务之间的表现差距是否缩小
- 同类错误是否减少
- 数日后能否从记忆重建
- 陌生变式能否完成
- 项目是否持续产生端到端增量

如果输入时间增加，但这些信号没有改善，应减少资料、缩小任务或改变练习方式，而不是简单延长学习时间。

## 11. 单次学习块模板

一次高认知学习块只处理一个主要问题：

```text
结果与验收
→ 预试/首试
→ 缺口诊断
→ 精准输入
→ 独立重建
→ 变式/项目
→ 验证讲解
→ 记录下一步
```

学习块结束前保存上下文：当前状态、测试结果、下一步和已知阻塞。具体时长根据任务和注意力调整，不用固定番茄钟代替结果。

## 12. 反模式

- 先看几个小时视频，再第一次写代码
- 照着示例敲完就立即进入下一章
- 卡住几分钟就让AI重写
- 在一个Bug上无目标地试错数小时
- 为了完整而阅读整份API文档
- 只重复原题，不做变式和项目迁移
- 把漂亮笔记当成掌握证据
- 已达到当前目标后仍无限深挖

## 13. 流程停止条件

当前流程已经覆盖获取、重建、间隔、迁移、AI求助、卡点处理和退出标准。继续增加步骤会提高记忆和记录负担。

下一轮优化应基于实际数据：哪一步经常被跳过、哪种内容耗时异常、哪些复测真正预测项目表现。
