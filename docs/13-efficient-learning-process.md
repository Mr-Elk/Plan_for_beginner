# 13 单次学习流程

高效学习不是少花时间，也不是让 AI 更快给答案。判断标准是：能否更快进入独立实践，数日后仍能重建，并在新场景中使用。

## 1. 先选入口

拿到任务后先判断当前状态：

| 状态 | 表现 | 从哪里开始 |
|---|---|---|
| 完全陌生 | 术语和输入输出都说不清 | 看一个最小例子，运行后立刻修改 |
| 知道概念 | 能复述，但不能写 | 先做 15–30 分钟预试，再补缺口 |
| 做过同类 | 能开始，但容易卡住 | 直接做项目增量或陌生变式 |
| 已经熟练 | 常见任务稳定完成 | 加限制、失败场景或远迁移 |

实践先行和知识先行不是二选一。缺前置时先补最小知识；能开始时不要用长课推迟第一次尝试。

## 2. 六步闭环

### 第一步：定义结果

用自己的话写出输入、输出、正常例子、边界和完成标准。范围大时，只保留一个能端到端运行的用户动作。

例：不要写“学习 FastAPI”，要写“客服提交订单号和问题后，接口返回已保存的工单；缺订单号时返回 422，重复提交时按约定处理”。

### 第二步：先做一次

在 15–45 分钟内从空白开始。目的是发现真实缺口，不要求第一次就正确。保留代码、报错和判断。

如果连第一行都写不出，先拆成数据、步骤和函数；仍无法开始，再进入最小知识输入。

### 第三步：诊断缺口

只选主要原因：

- 概念不懂：补定义、例子和反例；
- 语法或 API 不会：查官方最小示例；
- 设计不清：画数据流，拆输入输出和函数；
- 调试困难：做最小复现，增加观测；
- 范围过大：缩成一个纵向切片；
- 环境问题：保存复现，先用替代方案继续主线。

不要把“程序没跑通”笼统归为基础差。

### 第四步：精准输入

只学习能跨过当前缺口的内容。学习时必须做一项主动操作：预测输出、手算小例子、修改示例、解释反例或回答 AI 追问。

建议顺序：官方文档的相关小节、经过筛选的主教材、AI 分级讲解。不要为一个参数通读整套框架教程。

### 第五步：关闭资料重建

关掉完整答案，从空白重新写主要流程。随后补正常测试、失败测试和解释。如果使用过 A3/A4，核心部分必须在更低辅助下重写。

能看懂不等于能重建；能重建原题也不等于会迁移。

### 第六步：迁移与复测

至少改变一项业务、数据、接口或约束。例如把“新建工单”改成“批量导入并跳过重复订单”，而不是只换变量名。

核心能力在 1–3 天后安排一次短复测，在 1–2 周后通过项目或混合任务再次提取。复测失败时回到对应缺口，不整章重学。

## 3. 不同内容怎样调整

### Python、框架和工程

```text
用户流程
→ 官方最小示例
→ 一个纵向切片
→ 错误与测试
→ 修改需求
→ 重构和部署
```

重点是会查、会验证、会维护，不是背完整 API。

### 数据结构与算法

```text
重述题目和样例
→ 写朴素方案
→ 找瓶颈
→ 逐级提示
→ 解释复杂度
→ 关闭答案重写
→ 改约束做变式
```

看过答案后立即“会了”的题，只算练习。

### 数学与机器学习

```text
当前模型问题
→ 直觉和小数据
→ 必要公式
→ 手算或代码验证
→ 反例和适用边界
→ 回到指标或模型选择
```

推导深度服务当前应用，不追求无边界完整。

### LLM 应用

```text
定义输入输出和非 AI 基线
→ 最小调用
→ 保存失败样本
→ 加结构化输出、检索或工具
→ 建立固定评测
→ 比较质量、延迟、成本和风险
```

“回答看起来不错”不是验收。

## 4. 卡住时怎样求助

只要还在产生新假设、新观测或更小复现，就可以继续独立尝试。连续重复同一操作而没有信息增量时停止盲试。

求助时提交：预期、实际、已有尝试和最小卡点。AI 从 A1 开始；两次有效尝试后才升级。具体等级见 [AI 使用规则](04-ai-use-policy.md)。

## 5. 掌握与学习债务

达到当前目标等级就停止深挖：L1 能在引导下完成；L2 能独立完成常见任务和 T2 变式；L3 能处理失败、测试、部署、取舍和 T3 迁移。

以下内容记为学习债务：无法解释的复制代码、未验证的 AI 结论、跳过的失败测试、只看答案未重建的题、反复出现但未补理论的错误。每项债务必须有下一步和复测条件；核心债务未清前不新增主题。

## 6. 一次学习块的最小记录

- 本次要得到什么结果；
- 首试暴露了什么缺口；
- 使用了哪些资料和最高 AI 等级；
- 重建、测试和变式结果；
- 下一次复测时间；
- 未解决问题和下一步。

需要完整记录时使用[学习块模板](../templates/learning-session.md)。
