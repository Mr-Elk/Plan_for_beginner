# 00 项目章程

## 1. 项目目的

通过全日制、项目驱动、AI 辅助但不由 AI 代学的训练，使一名具有理工科大学背景、编程能力接近零基础的学习者，成长为能够独立设计、开发、测试、部署和解释 AI 应用的初级工程师。

训练同时服务两个目标：

1. 建立长期可迁移的计算机与软件工程基础。
2. 在合理时间内形成可用于求职和真实交付的作品与能力证据。

## 2. 学习者背景

- 22 岁，大学本科，原专业为遥感
- 当前编程能力按 A 级零基础处理
- 学过微积分、线性代数、概率统计，目前需要应用型复习
- 不排斥数学
- 可以借助翻译工具阅读英文资料
- 当前无工作，可每周投入 40 小时
- 学习动机以获得收入和进入新行业为主
- 不希望第一年继续走遥感方向

## 3. 培养目标

目标岗位按优先级排列：

1. AI 应用工程师
2. LLM 应用工程师
3. Python 后端工程师（AI 方向）
4. 初级 AI 全栈工程师

第一轮训练结束时，学习者应能：

- 从模糊需求中识别用户、问题、约束和验收条件
- 将问题拆成数据、流程、接口、模块和可验证任务
- 独立完成中等规模 Python 项目
- 使用 Git、Linux、测试和调试工具开展工程工作
- 设计并实现带数据库、认证、日志和部署的 Web 服务
- 阅读并使用常见技术官方文档
- 理解必要的数据分析、机器学习和深度学习概念
- 构建带评测、引用、安全边界和成本意识的 LLM 应用
- 在无 AI 环境下完成基础编程和需求变式任务
- 根据用户反馈、运行数据和失败案例迭代方案
- 使用Issue、PR、代码评审和交接文档与他人协作
- 清楚讲解自己的架构、取舍、Bug 和改进方向
- 提供在线演示、源代码、测试、README 和演示视频

## 4. 时间与节奏

- 规划周期：48 周
- 参考总投入：约 1,920 个有效小时
- 每周节奏：六天半
- 第 36 周开始用少量真实投递收集反馈
- 第 48 周完成第一轮训练，不把“找到工作”作为可由课程单方面保证的结果

周数是计划参数，不是自动晋级条件。实际晋级由能力矩阵中的证据决定。

## 5. 技术方向

### 主线

- Python
- Git、Linux、WSL2
- 数据结构、算法和计算机基础
- HTTP、SQL、PostgreSQL、FastAPI
- HTML、CSS、JavaScript、React 基础
- 测试、日志、类型、配置、Docker、CI 和云部署
- NumPy、Pandas、scikit-learn、PyTorch
- 模型 API、结构化输出、工具调用、Embedding、RAG
- 评测、安全、权限、Tracing、成本和可靠性

### 非主线

以下内容第一年不作为必修主线：

- 遥感/GIS 项目
- C++、Java 或多后端语言并行学习
- 训练基础大模型
- 分布式训练和复杂强化学习
- Kubernetes 和复杂微服务
- 多个 Agent 框架并行比较
- 高难度竞赛算法
- 以证书或课程观看时长替代项目证据

## 6. 学习环境

- 主开发环境：Windows + WSL2 Linux
- 部署环境：云端 Linux 服务器
- macOS：可用于验证跨平台体验，但不作为第二套并行主环境
- Python 项目统一使用 `uv` 管理环境与依赖
- 所有正式项目使用 Git
- 密钥只能通过环境变量或秘密管理方式使用，不得提交仓库

## 7. 成功定义

项目成功不以“完成 48 周内容”定义，而以以下证据定义：

- 通过全部核心阶段闯关
- 至少完成 1 个生产级旗舰 AI 项目
- 至少完成 1 个上线的完整 Web 项目
- 至少完成 1 个机器学习项目
- 保留 2–3 个体现基本功的较小项目
- 核心项目有自动化测试、部署、文档和可解释的设计决策
- 至少一个项目有真实或代理用户反馈，并能说明如何据此调整
- 至少一个核心项目有来自导师以外的人类评审或使用反馈，并形成修改闭环
- 能证明核心能力在陌生但相似的问题中可以迁移
- 能完成目标岗位常见的基础编程、后端和项目面试任务
- AI 辅助级别符合 [AI 使用与考核规则](04-ai-use-policy.md)

## 8. 基本原则

1. 项目牵引，知识服务于交付。
2. 螺旋学习，同一能力以不断升级的方式重复出现。
3. 证据晋级，不按观看时长或日历自动升级。
4. AI 提高反馈密度，但不能代替独立尝试。
5. 一个主题只保留一个主教材和一份官方资料。
6. 先掌握底层过程，再使用高层框架。
7. 每次变更都说明依据、影响和回退方式。
8. 先定义问题和验收标准，再选择技术和开始编码。
9. 作品数量服从证据质量，不用大量浅层 Demo 代替完整交付。
10. 实践负责暴露和验证问题，理论负责解释、抽象与迁移。
11. 记录必须服务下一步决策，不制造无用途的学习流水账。
