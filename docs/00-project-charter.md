# 00 项目章程

## 1. 背景

- 学习者：22 岁，遥感专业毕业，目前无工作。
- 编程起点：接触过，但基本不能独立完成程序。
- 数学：学过微积分、线性代数、概率统计；不排斥数学，需要按项目唤醒。
- 英文：可借助翻译工具阅读资料，直接阅读技术文档有困难。
- 动机：转行并提高收入，不把遥感作为第一选择。
- 条件：每周可投入 40 小时；有 Windows、WSL、Linux 云服务器、macOS 和 16 GB 显存设备；可使用付费模型 API。

## 2. 目标

第一轮训练结束时，学习者应能：

1. 独立完成后端优先的 AI 应用，从需求、开发、测试到部署形成闭环。
2. 解释 Python、HTTP、SQL、数据结构、操作系统和网络中的常用原理。
3. 为 LLM 功能建立输入输出契约、评测、失败处理、安全和成本边界。
4. 用代码、测试、部署、用户反馈和现场任务证明能力。
5. 依据岗位反馈继续补强，而不是依赖固定教程或 AI 代写。

## 3. 成功标准

训练成功不等于“学完 48 周”。至少需要：

- 一个可访问、可测试、可部署的旗舰项目；
- 一个传统机器学习闭环和一个 RAG 或工具工作流；
- G0–G7 的有效证据，核心编程和后端达到 L3；
- 能完成目标岗位常见的 Python、SQL、HTTP、调试和设计任务；
- 能进行 30 分钟项目答辩，说明取舍、失败、安全和成本；
- 有真实用户或外部开发者的评审—修改记录；
- 有简历、项目说明和试投递反馈。

获得 Offer 是重要结果，但不作为唯一毕业条件，因为岗位数量和招聘节奏不完全可控。

## 4. 范围

主线包括 Python、工程基础、数据结构与算法、计算机基础、FastAPI、PostgreSQL、薄前端、Linux/Docker、数据与机器学习、LLM API、RAG、工具调用、评测、安全和求职表达。

第一轮明确不做：

- 从零训练基础大模型；
- 竞赛算法和高难证明；
- 前端专家路线；
- Kubernetes、复杂微服务和多云架构；
- 同时学习多套后端或 LLM 框架；
- 为了利用原专业而强行加入遥感项目。

详细边界见[课程范围地图](10-curriculum-scope.md)。

## 5. 运行约束

- 48 周是规划窗口，不是硬性毕业日期。
- 每周目标为 40 个有效小时；无产出的被动观看、等待和无目的试错不计。
- 每两周只承诺一个主交付增量。
- 学习者可以使用 AI，但独立考核、变式和核心重建遵守指定边界。
- 课程按真实数据滚动生成，不提前写满 48 周日程。
- 健康、密钥、隐私、费用和证据真实性不能为进度让路。

## 6. 现实案例主线

默认用“小型电商售后与知识助手”贯穿阶段：

```text
文本整理 CLI
→ 售后记录工具
→ 带用户和数据库的 API
→ 可供客服使用的 Web 产品
→ 工单分类模型
→ 知识库检索或受控退款工具
→ 有评测、观测、安全和成本控制的系统
→ 旗舰项目与求职证据
```

项目题材可以更换，但能力门和验收标准不随题材降低。

## 7. 变更条件

只有目标岗位、周投入、培养方向、阶段门或重大外部条件变化时，才修改本章程。课程难度、框架小版本和单个项目功能由下层文件处理。
