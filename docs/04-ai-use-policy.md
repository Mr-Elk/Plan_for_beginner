# 04 AI 使用规则

AI 的作用是缩短反馈时间，不是替学习者产生能力证据。每项任务都要记录允许的最高等级。

## 1. 辅助等级

| 等级 | AI 可以做什么 | 适用场景 |
|---|---|---|
| A0 | 不使用 AI | 基线、独立考核、指定重建 |
| A1 | 提问、给方向、指出可能的知识缺口 | 第一次求助 |
| A2 | 比较方案、解释概念、帮助定位错误区域 | 已有两次有效尝试 |
| A3 | 提供局部代码或修改建议 | 非核心阻塞，之后必须重写和验证 |
| A4 | 给出完整实现 | 仅作研究材料，不产生独立证据 |

查语法和官方文档不自动算高辅助，但不能把完整答案伪装成资料查询。

## 2. 求助前后

求助前先写清：

- 预期结果；
- 实际结果；
- 已尝试的方法；
- 当前最小卡点。

收到回答后必须：

1. 逐项验证，不因语言流畅而相信。
2. 说明哪些部分采用、修改或拒绝。
3. 为修复补测试或最小复现。
4. 若使用 A3/A4，关闭答案后重写核心部分。

## 3. 各类任务的默认边界

| 任务 | 默认边界 |
|---|---|
| 学习新概念 | AI 可提问和讲解；学习者必须举例、反例并应用 |
| 项目开发 | AI 可审查和局部辅助；核心设计与代码要能解释、修改 |
| 调试 | AI 先帮助缩小范围，不直接覆盖原代码 |
| 算法练习 | 先独立写朴素方案；提示逐级升级 |
| 写文档 | AI 可起草；事实、命令和结果由学习者核对 |
| 独立考核 | 默认 A0；题目另有声明时从其声明 |
| 面试模拟 | AI 可出题和追问；见过答案的题不再作证据 |

## 4. AI 依赖的判断

出现以下情况就降低新内容、增加重建：

- 没有 AI 就无法开始；
- 代码能跑但不能解释数据流；
- 相似需求仍要重新索要完整实现；
- AI 生成部分长期没有测试；
- 日常练习很好，延迟独立任务明显下降。

恢复方法：缩小任务、回到 A1、关闭上下文重写、做改变业务和约束的变式。达到目标等级后再恢复正常辅助。

## 5. 安全边界

- 密钥只放在环境变量或受控密钥服务，不进入提示、代码或 Git。
- 不向公共模型提交个人数据、私有考核答案和未授权业务资料。
- 执行命令、数据库修改、外部消息和费用操作前先确认影响。
- AI 给出的依赖、命令和安全结论必须查官方资料或实际验证。

## 6. 证据隔离

辅导 AI 不得访问私有答案、隐藏测试和评分锚点。材料一旦泄露给学习者或辅导上下文，相关任务只能训练，不能用于独立晋级；重新生成等价但未泄露的任务后再测。
